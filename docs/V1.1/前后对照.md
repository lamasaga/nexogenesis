# ETP Agent 手册前后对照：v1.0 → v1.1

## 一、方向变化

| 维度 | v1.0 | v1.1 |
|---|---|---|
| 核心定位 | 建模一个人的思想，形成“有自我的思考伙伴” | 低摩擦地保存、复用和修正用户确认的思想 |
| 设计起点 | 先定义完整认知架构 | 先验证最小使用闭环 |
| 主要隐喻 | 记忆体、思维体、器官、宪法、自我演化 | Source、Thought、Synthesis、用户动作 |
| 成功依据 | 闭环、理论生态、脱钩指标、价值轨迹 | 准确保存、有效复用、纠正率、维护成本 |
| 用户模型 | Profile＋问题清单＋对话高权重 | 仅保存用户确认的 Thought，不建立权威人格模型 |
| 演化策略 | 系统深反思并提出或执行结构演化 | 真实问题重复出现后再增加最小机制 |

  v1.1 没有否定长期思想系统的目标，而是把“先证明有用”放到“先设计完整”之前。它把项目从一个预设完整的认知操作系统，退回为一个可以被证伪、可以与普通摘要比较的个人思考工具。

---

## 二、对象变化

| v1.0 对象 | v1.1 处理 | 原因 |
|---|---|---|
| Inbox / Archive | 保留为 Source 的流转位置 | 原始材料与溯源仍然必要 |
| Buffer 多类型碎片 | 取消长期 Buffer 体系 | 避免一份材料产生大量中间文件 |
| 十余种 Cards 类型 | 收束为 claim / question / tension | 先覆盖最常用思想单元，降低分类成本 |
| Profile 四件套 | 取消权威档案 | 防止把探索性表达固化为人格结论 |
| Theories 元理论 | 延后 | 未证明普通 Thought 无法满足使用需求 |
| Judgment 判断报告 | 合并进回答或 Synthesis | 避免回答、判断、回写、OutBox 多份重复 |
| Operations / Reflections | 取消强制 | frontmatter、结果报告和可选 Git 已足够支持早期追踪 |
| Divergence Record | 收束为 tension | 先用简单对象承载分歧，不新建独立制度 |

## 三、流程变化

### v1.0

```text
感知
→ 蒸馏
→ 暂存确认
→ Buffer
→ digest / construct
→ Cards / Profile
→ 六透镜判断
→ 辩证综合
→ OutBox
→ 回写
→ 操作日志
→ 轻反思
→ 周期深反思
→ 宪法提案 / evolve
```

### v1.1

```text
对话或材料
→ 提出最多 3—5 个候选
→ 用户确认
→ Thought
→ 在未来问题中检索复用
→ 必要时集中 review
```

  v1.1 将流程完成的标准从“所有环节都产生工件”改为“用户得到有帮助的回答，值得保存的内容被准确保存”。如果一次对话没有长期价值，允许零写入结束。

## 四、指令变化

| v1.0 | v1.1 | 变化 |
|---|---|---|
| `/talk` | `/talk` | 保留，明确默认不写入 |
| `/compile` | `/capture` | 从深度原子化改为少量候选提取 |
| `/digest` | 合并进 `/capture` 与 `/review` | 不再维护独立增量加工阶段 |
| `/construct` | `/review` | 从全局重构改为按真实摩擦集中维护 |
| `/analyze`、`/judge` | `/answer` 的风险升级 | 不再强制完整六透镜 |
| `/theorize` | 延后 | 有真实理论密度后再恢复 |
| `/reflect` | `/review` | 只反思内容与使用价值，不自动生产制度提案 |
| `/evolve` | 取消自动执行 | 手册修改始终由用户明确批准 |
| `/summarize` | 普通自然语言请求 | 无需独立系统器官 |

## 五、判断机制变化

| 方面 | v1.0 | v1.1 |
|---|---|---|
| 默认深度 | 完整六透镜＋综合 | 直接回答＋一个最强反例或限制 |
| 升级条件 | 对高价值内容强制执行 | 重要决策、争议、跨领域因果或用户明确要求 |
| 角度数量 | 六个全部独立产出 | 从六个候选角度中选 2—4 个真正相关的 |
| 事实判断 | 不裁决真假，只定位 | 事实允许核验真伪，因果比较解释，价值说明排序 |
| 生成力 | 生成问题数量 | 后续是否帮助理解、决策或产生有效复用 |
| 输出 | 判断报告＋回写＋OutBox | 回答；有复用价值时才保存 Synthesis |

## 六、治理变化

| v1.0 | v1.1 |
|---|---|
| 内容、结构、宪法三层权限 | 读取分析与实质写入两级权限 |
| 每个重要动作写日志 | 不强制操作日志 |
| 自主动作后立即 Git commit | 一个完整任务可形成一次提交；未启用 Git 时如实说明 |
| 十次会话自动深反思 | 用户触发或真实维护问题出现时 review |
| 系统可提出并执行结构演化 | 先给变更清单，用户批准后修改 |
| 四项脱钩指标触发流程 | 少量效用指标仅供观察，不自动授权扩张 |

## 七、明确删除或延后的内容

### 从 Agent 运行手册中删除

- “有自我的思考伙伴”作为工程事实；
- 双层器官架构和五条强制回路；
- 每次重要动作必须留痕；
- 新内容强制进入完整六透镜；
- 元理论的 embryo / contested / growing 生命周期；
- 固定 10 会话心跳和 30 轮蒸馏阈值；
- 用问题数量衡量生成力；
- 系统自主修改 AGENTS.md；
- 逐动作 Git commit；
- “没有日志的动作视为未发生”。

### 延后到出现证据后再决定

- GraphRAG 和向量库；
- 多 Agent 分工；
- 事件总线与事件溯源；
- Web 审批工作流；
- 自动训练或优化 Agent 手册；
- 多用户联邦、理论切磋与嫁接。

  延后不代表永远拒绝，而是要求每项机制先有一个可观察的进入条件。项目不再因为技术可用、行业流行或架构叙事完整而自动采用它。

---

## 八、仍然继承的价值

- 对话是重要思想来源；
- 用户观点、文档观点和系统观点必须区分；
- 来源必须可追溯；
- 冲突和未解决问题值得保存；
- 优先丰富已有内容，避免碎片膨胀；
- 用户拥有最终解释权和修改权；
- 内容应可迁移、可阅读，不被某个数据库锁定；
- 项目允许演化，但演化必须由真实使用证据推动。

---

## 九、方向决策建议

  建议先单独试用 v1.1，不覆盖 v1.0。完成至少 20 次真实对话后，再比较以下结果：哪些候选被用户保留，哪些旧思想真正帮助了新回答，用户纠正了多少次系统归因，维护流程消耗了多少时间。

  如果 v1.1 经常遗漏重要视角，再恢复部分判断透镜；如果文本检索找不到内容，再引入向量或图检索；如果三个 Thought 类型确实无法表达积累内容，再扩充类型。这样恢复的每一项复杂度都有实际理由。

  如果 v1.1 仍然显得繁琐，应继续删减，而不是把问题解释成自动化不足。如果它在低维护成本下稳定改善后续对话，才说明 ETP 的核心方向成立。
