# ETP v1.0 设计分析与梳理

> 本文档是对 `V1.0/AGENTS.md` 的元分析：它回答"为什么设计成这样"——每个决策从哪来、解决了 V0.5 的哪个病、又引入了什么新风险。阅读顺序建议：先看 §一（决策溯源），再看 §四（核心赌注），最后看 §五（剩余风险）——那里是下一代（v1.1 或 WebAgent 阶段）真正要解决的问题。

---

## 一、设计决策溯源表

v1.0 的每一条核心机制都能追溯到一次明确的用户选择或一条 V0.5 批判，不是凭空设计：

| # | 决策 | 来源 | 解决的 V0.5 问题 |
|---|---|---|---|
| 1 | 元理论**双向竞争**（涌现 + 外部对手） | 用户选择（第 1 轮澄清） | 无元理论层 |
| 2 | 透镜 4 **证伪 → 冲突**；判断 = 定位而非裁决真假 | 用户修正（"一切理论不过是有限理性的建构"） | 有组织无判断；单视角 analyze |
| 3 | 对话**自动蒸馏 + 暂存确认**，`author: user` 高权重 | 用户选择（第 3 轮澄清） | 建模对象错位：从"你读的"推断"你想的" |
| 4 | 权限三层模型，**内容+结构层自主**，宪法层报批 | 用户选择（比推荐更激进的一档） | 确认瓶颈；AGENTS.md 自我豁免 |
| 5 | 价值三维：**生成力（首要）**、解释力、可行动性 | 用户选择（剔除了"共振度"） | "价值"从未被操作化 |
| 6 | **双层架构**（记忆体 + 思维体） | 用户选择（未采纳推荐的单循环） | 单向流水线 |
| 7 | **行为闭环** + 脱钩指标 | 针对用户所选双层架构的已知风险，设计方主动加入 | 双层脱钩风险；无反思回路 |
| 8 | 问题清单入 Profile | 设计方推导 | 系统没有"用户当前在嚼什么"的表示 |
| 9 | 规律候选 = 特殊理论雏形 | 设计方推导 | "规律"无操作落点，且避免新目录膨胀 |
| 10 | Hooks 章节改为"诚实版"待实现清单 | V0.5 批判第 17 条 | 手册承诺了不存在的基建 |

**值得注意的一点**：决策 6 与决策 7 是一对——用户选了迁移成本最低的双层架构，设计方则用行为闭环和可量化指标来补偿其结构风险。这是本次设计中"用户偏好"与"设计方专业判断"协作的典型样本：选择归用户，风险归设计。

## 二、系统的一句话逻辑

> **对话是思想的发生现场，记忆体是思想的沉积，元理论是思想的观点化，六透镜是观点的检验方法，反思是整个系统对自身的观察与修正——五者构成一个闭环，而非一条管道。**

与 V0.5 最本质的区别不是多了哪些器官，而是**箭头方向**：V0.5 的所有箭头朝一个方向（Inbox → OutBox），v1.0 的箭头构成环（表达回到感知，反思回到一切）。

## 三、V0.5 批判 → v1.0 机制映射

| V0.5 的病（批判编号） | v1.0 的解法 | 解决程度 |
|---|---|---|
| 1. 单向管道无反思回路 | 反思器官（日志/轻反思/深反思/心跳） | 完整 |
| 2. 建模对象错位 | 对话蒸馏 + `author: user` 高权重 | 完整 |
| 3. AGENTS.md 自我豁免 | /evolve + 版本史 + 宪法提案流程 | 完整 |
| 4. 有组织无判断 | 判断引擎 + 价值三维 | 完整 |
| 5. 对话能力缺失 | 对话器官（默认模式 + 入场协议 + 问题清单） | 完整 |
| 6. 无元理论层 | 07-Theories + 生命周期 + 双向竞争 | 完整 |
| 7. 单视角 analyze | 六透镜 + 独立解读纪律 + 辩证综合 | 完整 |
| 8. 无规律/价值机制 | 规律候选（特殊雏形）+ 价值三维 | 完整 |
| 9. 产出不回流 | OutBox 判断结果回写被评对象；行为闭环 | 完整 |
| 10. 渐进阅读 vs 全量读取矛盾 | 入场协议沿用渐进式阅读；/construct 全量读取的上下文风险移交 WebAgent 阶段的图检索解决（见路线图 Phase 4） | **缓解，未根治** |
| 11. 数字暴政 | 保留少量阈值但全部标注"可经 /evolve 校准"，且阈值从"质量上限"改为"健康指标"（脱钩指标越界报警而非截断） | 部分 |
| 12. 类型学脆弱 | 未动（沿用 V0.5 类型集，仅新增 theory 类型） | **未解决，遗留** |
| 13. 加粗引用两难 | 未动 | **未解决，遗留** |
| 14. deprecated 淤积 | 未动（沿用不删除纪律） | **未解决，遗留** |
| 15. 确认瓶颈 | 权限分层：内容/结构层自主 | 完整 |
| 16. 时间语义缺失 | 价值轨迹（多次评估保留历史）开了个头 | 部分 |
| 17. 虚构基建 | §九 诚实清单 + 分阶段 | 完整（态度修正） |

**有意不解决的三条**（12/13/14）：类型学、加粗引用、deprecated 淤积。理由是 YAGNI——它们是真问题，但在系统还没有真实内容积累之前，优化它们没有抓手。深反思的摩擦模式会在它们真正咬人时暴露出来，那时再经 /evolve 处理。这是"把问题留给有证据的未来"而不是"假装问题不存在"。

## 四、四个核心赌注（设计哲学分析）

v1.0 的正确性依赖四个未被验证的赌注。它们应该成为深反思最早审视的对象：

### 赌注 1：行为闭环能约束结构双层
双层架构的脱钩风险用"五条强制回路 + 四个脱钩指标"来对冲。但这些约束本质仍是**提示词纪律**——依赖执行 agent 的自觉，没有代码级强制。**这是 v1.0 最薄弱的环节**，也是 WebAgent 路线图把"编排层代码化"放在 Phase 2 的原因：只有代码能真正强制"construct 后必须 judge"。

### 赌注 2：建构主义可以被操作化
"判断 = 定位不裁决"听起来对，但落地依赖三个具体载体：失效边界（冲突透镜产出有地方放）、生成的问题（生成力有计数方式）、竞争对手（理论关系有显式表示）。如果这三栏在实践中总是被敷衍填写（"暂无""待补充"），建构主义就会退化为口号。validate_theories.py（P1）的存在就是为了防止这种退化。

### 赌注 3：自主权 + 可逆痕迹 ≈ 安全
结构层自主的前提是"操作日志 + git commit"真的构成可逆性。但 git 快照只在每次自主动作后真的 commit 才有效——这又是一个纪律点。而且"可逆"恢复的是文件，恢复不了"用户信任的漂移"。缓解：脱钩指标中的异常会在 10 次会话内被深反思捕获，构成有界漂移。

### 赌注 4：用户话语高权重能修正建模错位
`author: user` 碎片权重最高，但用户随口之言 ≠ 深思熟虑。暂存确认是闸门，但闸门的效果取决于用户是否真的看那一页速览。如果用户习惯性一键确认，高权重反而放大噪声。观察指标：脱钩指标第 4 条（对话碎片占比）过高同样可疑——健康区间可能需要双向设限。

## 五、剩余风险清单（按优先级）

| 优先级 | 风险 | 现状 | 建议在何时解决 |
|---|---|---|---|
| 高 | 行为闭环无代码强制，依赖 agent 自觉 | 提示词纪律 | WebAgent Phase 2（编排层） |
| 高 | /construct 全量读取的上下文爆炸 | 未根治 | WebAgent Phase 4（图检索） |
| 中 | 雏形孵化质量不可控（自主孵化平庸理论） | 对抗相位 + 转正闸门兜底 | 运行 1-2 个月后评估 |
| 中 | 价值三维中解释力/可行动性仍主观 | 生成力可计数，其余靠判断 | 积累评估历史后校准 |
| 中 | 六透镜"独立解读"在单会话中实现成本高 | §6.2 纪律 + 未来 lens_runner.py 并行隔离 | WebAgent Phase 2 |
| 低 | 类型学脆弱、加粗引用、deprecated 淤积 | 有意遗留 | 深反思暴露证据后 /evolve |
| 低 | 对话长度阈值（30 轮）、心跳（10 会话）拍脑袋 | 标注可校准 | 深反思用摩擦数据校准 |

## 六、系统健康的可观测指标（汇总）

深反思每次心跳应输出这张仪表盘的当前值：

1. **脱钩四指标**（手册 §7.5）：被吸收率 / 被评估率 / 理论入场率 / 对话碎片占比；
2. **理论生态**：embryo / contested / growing 各多少个；平均对抗存活率；生成的问题总数；
3. **问题清单活力**：active 问题数、平均存活周期、answered 率；
4. **价值轨迹**：高价值卡片/理论的评分变化趋势；
5. **摩擦模式**：轻反思中重复出现 ≥3 次的摩擦点。

这些指标是"自我迭代"从口号变成工程的关键：宪法提案必须引用指标作为证据，而不是凭感觉。

## 七、从 V0.5 继承了什么（连续性声明）

批判是为了继承，以下 V0.5 资产在 v1.0 中原样保留：
- 渐进式阅读入口（ontology → domains → instances）；
- Buffer 三态中间层（scratch / digested / constructed）；
- 冲突作为一等公民（升级为冲突透镜 + 失效边界）；
- 来源标注纪律与幽灵链接禁令；
- hooks/LLM 分工理念（本次终于配上实现清单）；
- 不删除只标记 deprecated 的保守策略。
