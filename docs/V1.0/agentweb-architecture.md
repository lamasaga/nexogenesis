# AgentWeb 架构设计——ETP 的终局体系

> **定位**：本文档设计的是 ETP 的终局架构，而不是下一个版本。
> - **ETP v1.0**（`V1.0/AGENTS.md`）：单机体的"大脑"——markdown 底座 + 四器官；
> - **WebAgent**（`V1.0/webagent-roadmap.md` Phase 1–5）：给大脑以身体——界面、编排、检索；
> - **AgentWeb**（本文档）：让大脑进入社会——内部专职 agent 分工协作，外部与其他人的 AgentWeb 节点联邦交换。
>
> 设计前提：webagent 路线图 Phase 1–4 已完成（底座索引、编排层、Web 界面、GraphRAG 均已存在）。本文档从这里出发。

---

## 一、三个概念的边界

| 概念 | 一句话 | 类比 |
|---|---|---|
| ETP v1.0 | 个人思想建模系统（手册+文件） | 大脑 |
| WebAgent | ETP 的软件化（单用户 web 应用） | 大脑有了身体与感官 |
| **AgentWeb** | 多 agent 协作 + 多节点联邦的网络体系 | 人进入社会：内部有分工，外部有社交 |

**AgentWeb 的定义**：一个由专职 agent 组成、围绕个人思想底座（Thought Substrate）协作、并能与其他人的 AgentWeb 节点按协议联邦交换知识的网络体系。

---

## 二、设计原则（继承 v1.0 并扩展）

1. **底座主权**：markdown + git 是每个节点的事实之源与主权领土；任何代码、索引、数据库、甚至联邦交换，都不持有不可替代的信息（WebAgent 路线图的不变量在此仍然一票否决）。
2. **闭环靠强制**：行为闭环必须是事件订阅图，不是提示词纪律（v1.0 赌注 1 的终审判决）。
3. **分歧是一等公民**：建构主义立场的网络化延伸——agent 之间的分歧不投票消灭，存为"分歧档案"。
4. **无事件驱动，不专职化**：agent 数量是负债不是资产；先合并角色，忙不过来再拆分。
5. **本地宪法永远优先**：联邦来的对象无特权通道，一律以 `author: external` 走正常摄入流程。

---

## 三、总体架构：五层

```
┌────────────────────────────────────────────────────────────┐
│ L4 联邦层 Federation   节点间协议：出版 / 切磋 / 嫁接        │
├────────────────────────────────────────────────────────────┤
│ L3 协作层 Agent Mesh   专职 agent + 事件总线 + 分歧档案      │
├────────────────────────────────────────────────────────────┤
│ L2 内核层 ETP Kernel   对话/判断/理论/反思 四器官服务化      │
├────────────────────────────────────────────────────────────┤
│ L1 底座层 Substrate    markdown+git / 图索引 / 向量索引      │
└────────────────────────────────────────────────────────────┘
║ L0 治理层 Governance（垂直贯穿）：宪法 / 审批 / 审计 / 可逆  ║
```

## 四、L1 底座层：Thought Substrate

### 4.1 统一对象模型（ThoughtObject）

把 v1.0 的全部对象抽象为带 schema 的统一模型，一切 agent 经 API 读写，不直接碰文件：

```json
{
  "id": "learning-as-compression",
  "type": "card | buffer | theory | question | judgment | reflection | journal | divergence",
  "status": "embryo | contested | growing | ...",
  "author": "user | system | document | external",
  "provenance": ["来源链：对象 id 或外部锚点，可逐级回溯"],
  "relations": [{"target": "...", "type": "...", "note": "..."}],
  "timestamps": {"created": "...", "updated": "..."},
  "body_ref": "markdown 文件路径（事实之源）"
}
```

- `divergence`（分歧档案）是新增的一等对象（§6.3）；
- `provenance` 是强制字段：任何对象必须能回溯到原始证据链——v1.0"禁止无来源观点"的代码化。

### 4.2 存储与索引

- markdown + git：事实之源（唯一不可替代层）；
- 图索引：卡片 relations + 理论 competes-with + provenance 链；
- 向量索引：语义检索（GraphRAG 入场）；
- 索引可随时从 markdown 全量重建。

## 五、L2 内核层：ETP Kernel

v1.0 四器官的服务化产物（webagent Phase 2–3 的完成态）：

| 服务 | 来自 | 职责 |
|---|---|---|
| 对话服务 | 对话器官 | 带观点入场协议、对话蒸馏、问题清单维护 |
| 判断服务 | 判断引擎 | 六透镜 worker 池 + 辩证综合、价值三维 |
| 理论服务 | 元理论层 | 生命周期状态机、对抗组织、规律候选扫描 |
| 反思服务 | 反思器官 | 心跳 daemon、脱钩指标、摩擦模式、宪法提案草稿 |

Kernel 对 L3 暴露的是**能力接口**，Mesh 中的专职 agent 是这些能力的"人格化使用者"。

## 六、L3 协作层：Agent Mesh

### 6.1 专职 agent 谱系（从器官分化，不凭空造）

| Agent | 分化自 | 职责 | 模型档位 |
|---|---|---|---|
| **前台 Interlocutor** | 对话器官 | 唯一面向用户的话事人；带观点入场；代表全系统说话 | 大模型 |
| **编纂 Scribe** | 摄入器官 | 对话蒸馏、/compile、Buffer 生产 | 小模型 |
| **馆员 Librarian** | 摄入器官 | /digest /construct、卡片维护、链接治理 | 小模型 |
| **评审团 Panel** | 判断引擎 | 六个透镜 worker（并行隔离）+ 综合者 Synthesizer | 小模型 ×6 + 大模型 ×1 |
| **理论家 Theorist** | 元理论层 | 雏形孵化、组织对抗（引入外部对手）、规律扫描执行 | 大模型 |
| **哨兵 Sentinel** | 反思器官 | 心跳、指标、摩擦模式、宪法提案草稿 | 小模型 |
| **守门人 Gatekeeper** | 治理需求 | 权限检查、审批路由、宪法版本史 | 纯代码，无 LLM |
| **侦察兵 Scout** | （新增） | 外部世界感知：订阅源、新论文、用户关注主题监测，产出 Inbox 候选 | 小模型 |

**关键约束**：用户只与前台对话。其余 agent 的产出要么写入底座（用户可浏览），要么进入审批收件箱（用户可裁决）——**任何 agent 不得直接打断用户**。这是 V0.5"确认瓶颈"教训在 multi-agent 时代的形态：打扰权是稀缺资源，集中管理。

### 6.2 协作机制：事件总线 + 黑板

- **触发走事件**（消息模式）：一切 agent 间触发经事件总线。核心事件类型：
  `buffer.created` / `construct.done` / `theory.embryo.hatched` / `theory.contested` / `judgment.done` / `metric.violated` / `approval.requested` / `approval.decided` / `journal.appended`
- **状态走黑板**（共享模式）：共享状态一律写底座，agent 不互相传私有状态。
- **行为闭环 = 事件订阅图**（示例）：
  ```
  construct.done ──► Panel.evaluate ──► judgment.done ──► 回写卡片 + Scribe 归档
  metric.violated ──► Sentinel 深反思 ──► approval.requested ──► 用户收件箱
  theory.embryo.hatched ──► Theorist 组织对抗 ──► theory.contested
  ```
  v1.0 的五条强制回路在这里全部成为订阅关系——**闭环从纪律变成拓扑**。

### 6.3 分歧档案（Divergence Record）

建构主义的工程化：以下三类分歧必须存为一等对象，禁止和稀泥：
1. Panel 内部透镜间的分歧（辩证综合的产出）；
2. 元理论之间的竞争（contested 相位的对抗记录）；
3. 联邦切磋中节点间的分歧（§7.2）。

分歧档案包含：双方立场、各自证据、不可调和点、各自失效边界、后续验证线索。它是规律候选与宪法提案最富的矿脉。

## 七、L4 联邦层：Federation

### 7.1 节点与身份

- 一个节点 = 一个用户的思想底座 + 本地宪法 + 一对密钥（节点身份）；
- 节点间不共享原始库——**交换的是"可出口的建构"**（理论、判断报告），且每次出口必须经用户批准 + 脱敏检查（Gatekeeper 执行）。

### 7.2 三种交换模式

| 模式 | 说明 | 类比 |
|---|---|---|
| **出版 Publish** | 理论以只读包发布（含命题/证据基/失效边界/provenance），他节点可读可引 | 论文 |
| **切磋 Duel** | 两个节点的竞争理论结构化对抗：双方 Theorist 出庭，冲突透镜主持，产出共同分歧档案 | 学术辩论 |
| **嫁接 Graft** | 引入外部理论作为本地对抗对手——v1.0"双向竞争"的网络化 | 引进物种 |

### 7.3 主权规则（不可协商）

1. 联邦来的对象一律 `author: external` 入 Inbox，走标准 compile 流程，**无特权通道**；
2. 本地宪法（权限模型、价值标准、六透镜集合）不接受联邦层修改；
3. 出口内容逐条用户批准，默认拒绝；
4. 切磋产出的分歧档案归双方节点共有，各自本地保存副本。

## 八、L0 治理层：Governance（垂直贯穿）

| 机制 | 实现 |
|---|---|
| 宪法执行 | Gatekeeper 为纯代码策略引擎：每个事件与写操作过权限检查（三层模型） |
| 审批收件箱 | 全系统统一的异步收件箱：蒸馏确认 / 理论转正废弃 / 宪法提案 / 出口批准；带默认策略与超时升级规则，防止审批积压重演确认瓶颈 |
| 审计 | 事件溯源：全事件日志可回放；任何对象沿 provenance 回溯到原始证据 |
| 可逆性 | git 快照 + 事件重放双保险 |
| 工具安全 | agent 的外部工具（MCP 等）白名单制；Scout 的采集源白名单制 |

## 九、技术栈映射与演化路径

### 9.1 与 webagent 路线图的衔接

```
webagent Phase 1（基建）   ──► L1 底座 schema 化
webagent Phase 2（编排）   ──► L2 Kernel 服务化（Mesh 的胚胎）
webagent Phase 3（Web）    ──► 前台 + 审批收件箱雏形
webagent Phase 4（GraphRAG）──► L1 索引完备
webagent Phase 5（多用户） ──► 多节点的温床
──── 以下进入 AgentWeb 范畴 ────
Phase 6：事件总线抽离 + agent 专职化（Mesh 成型）
Phase 7：联邦协议（第一个实验：两个节点的理论"切磋"）
```

### 9.2 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 事件总线 | asyncio 队列 → Redis Streams/NATS | 单体够用就不上中间件（原则 4） |
| Agent 运行时 | Python（etp 包分化）+ LLM provider 抽象 | 小模型工人池 + 大模型综合，控制成本 |
| 内部协议 | JSON 事件 schema（受 ThoughtObject 约束） | schema 先行，防止 agent 间方言漂移 |
| 联邦协议 | HTTPS + 节点密钥签名；交换包为签名 JSON | 无需实时，批式交换即可起步 |
| 前端 | 对话 + 看板 + 图谱 + 审批收件箱 + 指标仪表盘 | 已有 Phase 3–4 基础 |

### 9.3 成本经济学（粗略）

评审团一次完整判断 ≈ 6 次小模型调用 + 1 次大模型调用；前台对话按大模型计；其余 agent 全部小模型。**大模型只出现在三处：前台、综合者、理论家**——这三处是"判断力"的所在，其余都是体力活。

## 十、风险与反模式（诚实清单）

| 风险 | 说明 | 对策 |
|---|---|---|
| 复杂度爆炸 | 8 个 agent = 8 个维护面；multi-agent 圈的最大失败模式 | 原则 4：无事件驱动不专职化；初期 Scribe+Librarian 合并、Sentinel+Gatekeeper 合并 |
| 审批官僚主义 | 审批收件箱积压 = V0.5 确认瓶颈的网络版 | 默认策略 + 超时升级 + 每周审批 SLA 进入哨兵指标 |
| 事件总线过早引入 | 单体编排足够时上总线是过度工程 | Phase 6 前保持单体；总线抽离以"订阅者 >3"为触发条件 |
| 联邦隐私泄漏 | 思想底座的出口风险远高于普通数据 | 逐条批准 + 脱敏检查 + 默认拒绝；出口日志单独审计 |
| 分歧档案淤积 | 只存不用的分歧会变成新的 deprecated 坟场 | 哨兵每季度扫描：无后续验证线索的分歧档案降级为 dormant |

## 十一、不变量清单（任何演化不得违反）

1. 删除全部代码与索引，只留 markdown + git，节点信息零损失；
2. 用户只被前台打扰；其他 agent 永不直接发起对话；
3. 任何对象可沿 provenance 回溯到原始证据；
4. 分歧以档案保存，不以投票消灭；
5. 本地宪法优先于联邦协议；联邦对象无特权通道；
6. 大模型只用于判断力岗位（前台/综合/理论家）。

---

## 十二、这张架构图的"第一块砖"

AgentWeb 是终局，不是起点。回到当下，通往它的第一块砖仍然是 webagent 路线图的 Phase 1（P0 脚本三件套）——因为本架构的一切强制（事件、schema、provenance）都建立在"确定性基建真实存在"之上。V0.5 的教训在最开始就说过了：**手册承诺的基建，必须与手册同步存在。**
