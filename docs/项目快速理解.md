# Nexogenesis 项目快速理解

> 写给第一次接触本项目的人。不堆术语，只讲「它是什么、怎么转、有什么特点」。  
> 更细的契约与命令见 [`AGENTS.md`](../AGENTS.md)；技术设计见 `docs/` 下各专题文档。

---

## 一句话

　　**Nexogenesis（智构涌现）是一个「用对话和阅读慢慢长出知识结构」的个人知识系统**——你的笔记、文章、讨论都落在本地 Markdown 文件里；程序负责规矩和写入安全，AI 负责理解和整理；值得留下的想法经你点头后才进库。

---

## 它解决什么问题

　　普通笔记容易变成「堆材料」：摘抄很多，却说不清自己到底相信什么、哪些观点在打架、旧想法和新材料怎么接得上。

　　Nexogenesis 想走的是另一条路：

- 把**已经想清楚、愿意负责**的内容，收成一张张**卡片**（有类型、有关系、有来源）；
- 把**还没定型**的内容，先放在**草稿层**，不急着升格成「真理」；
- 日常主要是**聊天、分析、追问**；只有该沉淀时，才走一小段确认流程。

---

## 三层分工（先记住这个）

```text
你 + AI（思维）     →  聊天、判断、提议要不要记下什么
Harness（程序）     →  检查格式、统一写入、建索引、防写坏
Markdown 文件（底座）→  真正的知识内容，删了程序也能读
```

| 谁 | 干什么 | 不干什么 |
|----|--------|----------|
| **你** | 决定记什么、改什么立场、批不批准写入 | — |
| **AI** | 理解材料、找关联、写候选、组织回答 | 不经你同意改卡片 |
| **程序** | 校验、原子写入、生成目录视图、图/RAG 索引 | 判断内容好坏 |

　　**底座纪律**：约定文件夹里的 **Markdown 是内容的唯一权威**；图索引、搜索索引都可以删掉后从 Markdown 重建。Git 用来留历史、回滚，**不是**思想本身。

## 文件夹在干什么（地图）

```text
00-Inbox/          刚放进来的原文（书、论文、网页导出…）
05-Buffer/         编译后的「质料」——还没承诺成正式知识
01-Cards/          正式知识卡片（扁平存放，靠关系而不是文件夹分类）
02-Profile/        你的问题清单等档案
03-Archive/        已处理完的原文
04-OutBox/         某次分析、讨论纪要（可检索，默认不算「已定结论」）
06-Journal/        系统操作大事记
```

　　可以记成两条线：

1. **对话线**：聊 → 偶尔「记一下」→ 你确认 → 进卡片或问题清单  
2. **阅读线**：Inbox → 编译成 Buffer → 消化进卡片 → 必要时再整理整体结构  

---

## 两种「东西」：质料 vs 卡片

　　这是本项目最容易搞混、也最重要的区分。

| | 质料（Buffer） | 卡片（Card） |
|--|----------------|--------------|
| **像什么** | 厨房里的食材、剪报 | 菜谱上的一道道「认定」 |
| **从哪来** | 编译文档、对话草稿 | 你确认后的写入 |
| **特点** | 有摘录、有来源，**还不承诺结构** | 有类型、有关系、可长期复用 |
| **七种卡片** | — | 领域、主张、现象、模型、方法、实体、冲突 |

　　**问题清单**单独放在 Profile，不算卡片类型；**阶段性长文回答**可以放 OutBox，需要时再拆成卡片。

## 日常怎么用（对话为主）

　　你**不需要**每次念命令名。理想体验是：

1. **正常聊**：问问题、要分析、要反驳——AI 会在后台带上相关卡片和原文片段。  
2. **偶尔被轻问一句**：如果出现很值得留下的判断，系统可能问「要不要记下？」——你可以忽略。  
3. **你说「记一下」**：给出少量候选（自然语言），你改完再批准。  
4. **批准后**：程序一次性写入，并更新索引。

　　**分析默认留在对话里**，不会自动变成报告文件；**写入永远要你确认**，对话捕获不会自动入库。

### 思维体在后台补的三样东西

| 名字 | 大白话 |
|------|--------|
| **长期记忆** | 已有卡片和它们之间的关系（像一张网） |
| **工具书** | 归档原文、讨论稿、Buffer 片段——用来查细节、引证据 |
| **短期记忆** | 最近大约十次对话的焦点、张力、引用过哪些卡 |

　　每一轮回复前，程序会拼一块**不大但很贴题**的上下文：既有你聊过的线头，也会尽量接上「没想到但合理」的旧卡片，必要时把对立观点也摆进来。权重可在 `schemes/default/attention.yaml` 里调。

## 读文章时怎么用（摄入线）

　　当你往 `00-Inbox/` 放了材料，典型顺序是：

```text
compile   把长文拆成 Buffer 质料（按意义单元，不是按章节硬切）
   ↓
digest    对照已有卡片，决定丰富谁、新建谁、要不要记冲突
   ↓
construct 卡片多了以后，做结构体检和整理（领域、冲突、关系）
```

　　每一步都是：**程序生成任务说明 → AI 产出结果 → 你或 `--auto` 自检后 → 统一写入**。中间文件留在 `.nexogenesis/tmp/`，方便事后查看。

　　说「开始消化 / 开始建构」或加 `--auto`，表示你授权这一轮自动自检落盘；**不是**让 AI 随便改库。

## 检索：两本书同时翻

　　问一个问题时，系统会从两个方向找材料：

| 方向 | 找什么 | 比喻 |
|------|--------|------|
| **结构图** | 相关卡片、关系、冲突 | 翻你自己的概念网 |
| **质料搜索** | 原文摘录、讨论、归档 | 翻书架和剪报盒 |

　　合并后交给 AI 回答。讨论稿在搜索里会标成「研讨草稿」，**不能**当成你已经认定的主张。

　　统一入口：`python -m nexogenesis retrieve --query "…" --mode talk`

## 七个特点（为什么不是普通笔记软件）

1. **文件即真相**：不绑死某个数据库；换电脑、删索引，Markdown 还在。  
2. **写入有闸门**：改卡片必须走 `write --batch`，先校验再落盘，失败不留半成品。  
3. **质料与结论分层**：没想清楚的内容不会假装成正式知识。  
4. **冲突要露面**：鼓励用「冲突卡」记录对立，而不是只留赢家。  
5. **领域是骨架**：用「领域卡」组织空间，而不是深层文件夹。  
6. **对话优先、结构其次**：平时像聊天；整理结构是显式模式，不是日常税。  
7. **复杂度要证明**：新机制必须能说清解决什么摩擦、怎么撤回——避免系统越养越重。

## 五分钟上手

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -e ".[dev]"

python -m nexogenesis init      # 建目录、装 hook
python -m nexogenesis doctor    # 自检
```

**只想聊天、用已有库：**

```bash
python -m nexogenesis memory start --title "今日"
python -m nexogenesis retrieve --query "你的问题" --mode talk
```

**刚丢了一篇 PDF/文章进 Inbox：**

```bash
python -m nexogenesis compile --plan    # 先看怎么分批
python -m nexogenesis compile         # 生成编译任务
# AI 写完 response 后：
python -m nexogenesis compile --check-responses
python -m nexogenesis compile --apply
```

**命令全集**：见 [`AGENTS.md` §5.0](../AGENTS.md)（底座 / 摄入 / 检索 / 记忆 一张表）。

## 和 AI 协作时，它读什么、守什么

**每次重要操作前，AI 应读：**

- `AGENTS.md`（规矩）
- `01-Cards/_meta/ontology.md`（卡片类型）
- 与问题相关的卡片或自动生成的领域/冲突视图

**AI 必须遵守：**

- 不绕过写入入口直接改卡片  
- 区分「你的话 / 文档的话 / 系统推测」  
- 优先丰富已有卡，少造空卡  
- 捕获须你批准  

**你不必遵守：** 背诵全部 CLI；用自然语言说意图即可。
