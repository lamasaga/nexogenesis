## 1. 一句话结论

　　本轮 talk/涌现能产出有齿感的综合，**主要靠「技能契约 + 定向 retrieve + 人工二次捞卡」的组合**，而不是单次 Context Package 自动组装到位。提示词侧的关键动作是：先钉用语与问题轴，再把库内 conflict 当支架做相位重组；工具侧的短板是 **抽象宏观提问下的种子噪声**、**Profile 透镜偏弱**、以及 **涌现结果无法回流检索**。优化应优先打检索打分/去噪、元概念总览卡、以及「对话涌现 → 可选捕获」的轻仪式，而不是再加长 talk 系统提示。

## 3. 提示词组合过程（Agent 侧实际在拼什么）

　　此处「提示词」不单指发给子模型的字符串，而是 **每一跳 Assembled Working Set**：技能契约 + 检索包 + 人工加料 + 用户原话 + STM。下面按真实顺序拆。

### 3.1 固定层：技能与活契约（每轮 talk 应先装）

　　触发「基于知识库讨论」后，第一组装块来自 `nexo-talk/SKILL.md`，约束可压缩为：

1. **Grounding 顺序**：constraint-layers → thinking-body → retrieval-design → `02-Profile/`。  
2. **工作流**：`memory status|start` → `retrieve --mode talk` → 读 Context Package（分 structure / material，分 user/document/system/nascent）→ 回答 → 可选 `memory update` → 强信号才问捕获。  
3. **硬纪律**：分析默认留对话；禁止对话路径写卡；无 `theory_status: active` 不得宣称「从理论 X 视角」。

　　实际执行上：**完整读了 skill；thinking-body 只读了前段目标/STM 定义；Profile 领域理念几乎未展开，领域思维范式只扫到与通论相关的两条推理模式**。也就是说，契约层是「声明完整、执行偏技能+检索」，Profile 透镜装载不足（后文 §5.3）。

### 3.2 查询层：如何把用户话改写成 retrieve query

　　用户原话往往短而抽象；Agent 不会原样丢给检索，而是做 **轴钉定 + 同义词展开**：

| 用户话 | Agent 实际 query 策略 | 意图 |
|--------|----------------------|------|
| 古典与现代分野有哪些 | `古典经济学与现代经济学的分野 有效需求 萨伊法则 流动性偏好 自然失业率` | 把「分野」落到库内已有机制词，避免只撞到曼昆「十大原理」热词 |
| （续） | 第二次：`萨伊法则 节俭悖论 充分就业特殊情形 流动性偏好与储蓄投资 古典公设` | 用通论消化后的卡名作锚，补第一枪噪声 |
| 不稳定从哪来 + 涌现 | `经济不稳定根源 内生金融不稳定 外生冲击 明斯基 投资崩塌 有效需求 资本边际效率 流动性偏好` | 直接对齐 conflict 两造与 MEC/选美簇 |
| 复盘噪声时 | `不稳定从哪来：外生冲击 vs 内生金融过程 明斯基 MEC` | 用焦点句复现「仍会召回跑题卡」 |

　　**组合原则（本轮归纳）**：

- **先机制词、后学派标签**：单用「古典/现代」易漂到微观权衡卡；加上有效需求/萨伊/自然率才接到宏观轴。  
- **多枪补洞**：第一枪看 seeds；噪声大则第二枪用卡 id/术语重打，而不是加长同一句。  
- **涌现不另开检索模式**：仍用 `--mode talk`；「新想法」靠回答策略（相位重组 + 标明 system），不靠换 retrieve 开关。

### 3.3 加料层：Context Package 不够时人工补的「第二提示词」

　　双轨包返回后，Agent 常发现 **core 命中对、expansion/seeds 脏**。本轮采取的补偿组装是：

1. **Shell/Python 按卡名关键词批量读正文**（不稳、明斯基、MEC、选美、大政府、主动稳定化等），把 10+ 张卡的核心思想/对立双方压进工作记忆。  
2. **用卡 id 当硬锚**写对照表（三公设、充分就业特例、利率之争、合成谬误、自然率、不能钉住失业等）。  
3. **显式归因指令（对内）**：document = 卡内主张；system = 三时钟、自然率嵌脆弱度等综合；禁止把 system 说成库内已有 Card。

　　这一层等价于 **手写的 dense prompt**：比 Context Package 的 excerpt 更完整，也更贵（全卡扫描）。它暴露了：当前 automatic package 的 excerpt 截断（「…（摘录截断）」）对深思不够。

### 3.4 回答层：如何把「讨论」与「涌现」写成不同提示姿态

| 姿态 | 提示结构（对内模板） | 本轮落点 |
|------|----------------------|----------|
| 讨论/分野 | 钉用语 → 按问题轴列表 → 每轴引用卡 → 压缩对照表 → 追问下一轴 | 就业/需求/利率/货币预期/方法/不稳六轴 |
| 深思+涌现 | 复述库内对立 → 指出二元 incompleteness → 提出 3–5 个可命名假说（标 system）→ 接回政策含义 → 轻问是否捕获 | A–E 五想法；问记 A/B |
| 运作自评 | 好/不足分栏 → 总评一句 → 可执行补洞排序 | 库存够深、检索钝、涌现无回流 |

　　涌现姿态的关键提示技巧：**不要求「全新理论」**，而要求「把已有卡做相位对齐后给出可检验命题」——这与 AGENTS「意义聚合与知识结构涌现」一致，也降低幻觉式发明。

### 3.5 STM 层：跨轮提示的薄状态

　　`memory start --title "古典与现代经济学分野"` 后，`memory update` 写入：

- focus：古典与现代分野 → 后改为「不稳定从哪来：外生冲击 vs 内生金融过程」  
- cite：充分就业特例、利率之争、不稳根源之争、明斯基…  
- tension：充分就业特例 vs 自然率；外生 vs 内生  

　　作用：给后续轮次一个 **短提示前缀**（当前问题 + 未决张力 + 已引卡）。不足：`turn` 计数未见有效递增利用；两卷 session 并存时，旧卷「知识结构缺口」与新卷并行，Agent 主要靠对话上下文而非严格只读当前卷。

### 3.6 提示词组合总图（本轮）

```text
用户原话
   │
   ├─► nexo-talk 契约（禁止写卡、归因、retrieve 流程）
   ├─► query 改写（机制词展开 / 多枪）
   │         │
   │         ▼
   │   retrieve → Context Package（structure seeds/nodes + RAG）
   │         │
   │         ├─► 若噪声大：Shell 定向读卡（人工 dense 上下文）
   │         └─► 若够用：直接用 excerpt + 深读节点
   │
   ├─► Profile（本轮弱装载）
   ├─► STM focus/cites/tensions
   │
   ▼
回答模板（讨论表 或 涌现假说） + 归因标签 + 可选捕获轻问
```

## 4. 各类型工具如何被调用

### 4.1 工具类型地图

| 类型 | 具体工具 | 本轮用途 | 调用密度 |
|------|----------|----------|----------|
| 技能/契约读取 | Read（`nexo-talk`、thinking-body、偶尔 retrieval-design） | 装载 talk 纪律 | 每任务 1 次起步 |
| 双轨检索 | `python -m nexogenesis retrieve --mode talk` | 主上下文包 | 分野 2 次；不稳 1–2 次；复盘再 1 次 |
| 短期记忆 | `memory status` / `start` / `update` | 开卷、改 focus、记张力 | 开谈时 + 加深时 |
| 定向读卡 | Shell + Python 扫 `01-Cards` | 补全 package 截断、组机制链 | 分野 1 次；不稳 1 次（大批量） |
| 元检查 | `digest --plan`、Inbox 列表等 | 不在本谈主路径；前后会话用于状态 | 本谈较少 |
| 子代理 Task | （本谈未用） | 消化/编译并行时用，talk 深思未委派 | 0 |
| 写入 | Write → `04-OutBox/...` | 仅本复盘；谈中无 write --batch | 1（本文） |

### 4.2 调用顺序（以「不稳定深挖」为例）

1. **Read** `nexo-talk`（若本会话已读可省略，加深轮仍应确认「不写卡」）。  
2. **`retrieve`** 用不稳机制词 query → 写 `.nexogenesis/tmp/retrieve/context.yaml`。  
3. **Read** context.yaml 前部 seeds/nodes；判断噪声（效率平等、管理替代等是否混入）。  
4. **`memory update`** 切 focus / 补 cite / tension。  
5. **Shell 批量读卡** 不稳簇全文要点（冲突、两造 claim、MEC、选美、大政府、时滞）。  
6. （可选）**Read** thinking-body 提醒：涌现默认留对话、强信号才敲门。  
7. **生成回答**（无 CallMcp、无 write batch）。  
8. 用户若说「记一下」才转 emerge（本轮未发生）。

### 4.3 工具分工的有效性判断

| 工具 | 有效处 | 失效处 |
|------|--------|--------|
| `retrieve` | 能稳定召回 `经济不稳定根源之争` 及大政府/AD-AS 相关边 | seeds/expansion 易混入微观热卡；excerpt 截断不利深思 |
| 定向读卡 | 深思与涌现的真正质料来源 | 绕过官方注意力组装，成本高，且不更新「官方」检索质量 |
| STM | 焦点从分野切到不稳时有记录 | 对回答内容约束弱；turn/档案复用规则未严格吃进提示 |
| Profile | 契约要求读 | 本轮几乎未改变推理路径 |
| OutBox Write | 适合过程债 | 与 Card 索引隔离，下轮 talk **检索不到**本复盘除非人工打开 |

## 5. 遇到的问题（按严重度）

### 5.1 P0 — 抽象提问下的检索种子噪声

**现象**

　　「古典/现代分野」「不稳定根源」类问题，structure seeds 多次混入：效率与平等权衡、管理—替代困境、贸易补偿、人力资本与信号、价格管制等。core 里往往已有正确 conflict，但注意力被脏种子稀释。

**对提示词的后果**

　　Agent 必须额外写「忽略下列跑题枢纽」的隐性指令，或直接放弃 package、改扫卡——**双轨设计的主路径被旁路**。

**根因猜想**

　　图种子可能偏爱高连接/近期热 conflict；query 中「经济」「市场」等宽词与曼昆簇共现高；抽象「分野/根源」缺少专指 entity。

### 5.2 P0 — 涌现有语义、无结构回流

**现象**

　　三时钟、自然率嵌脆弱度等只存在于对话与本 OutBox；下轮 `retrieve` 仍搜不到这些命题。

**对提示词的后果**

　　无法写「基于上轮涌现假说继续推演」的可靠前缀，只能靠 STM 一行 focus（信息量远小于假说本身）。

### 5.3 P1 — Profile 透镜装载失败（执行债）

**现象**

　　skill 要求读 `02-Profile/`；本轮实际几乎只用卡片簇推理。范式文件里也缺少「脉冲/放大/相位」类默认路径。

**后果**

　　「领域怎么想」依赖 Agent 临场风格，而非 Profile 稳定塑形。

### 5.4 P1 — 元概念卡缺失导致提示里必须口头钉用语

**现象**

　　「古典」在库内至少三义（史学古典、通论靶子、现代短长期分层中的长期侧）。提示词组合时要用一整段「先钉用语」——说明缺总览 conflict/claim。

### 5.5 P2 — Context Package excerpt 对深思过短

**现象**

　　节点常「…（摘录截断）」；涌现所需的机制链（MEC→选美→融资→大政府）要靠二次读全文。

### 5.6 P2 — 库存缺口限制涌现的可检验性

**现象**

　　危机形态学（Kindleberger 等）未入库；想法「份额可检验」缺乏案例骨架。提示词只能停在机制抽象。

### 5.7 P2 — 与并行 ingest 代理的注意力竞争（会话背景）

**现象**

　　同日大量 digest/compile 子代理运行；talk 深思时 Agent 上下文还可能夹带 ingest 状态。本谈后半已纯 talk，但用户时间线上「消化未完又讨论」会造成焦点切换成本。

## 6. 可优化处（建议，按性价比）

### 6.1 检索：抽象宏观 query 的去噪与重排（工程）

1. **talk 模式对 domain 加权**：query 命中「不稳定/有效需求/流动性」时，提升 `金融权力投机与内生不稳定`、`短期波动与AD-AS` 域种子权重，降低纯微观政策权衡域。  
2. **种子多样性惩罚**：同一 hop 内若已有宏观 conflict，抑制再塞效率—平等类高连接但低相关节点。  
3. **query 改写助手（可选）**：CLI 或 skill 内提供「宏观分野/不稳根源」模板扩展词表（萨伊、MEC、明斯基、自然率…），减少 Agent 临场漏词。  
4. **深思档 excerpt**：`--mode talk` 增加 `deep_excerpt` 或对 conflict/claim 返回对立双方全文槽。

### 6.2 提示词：把本轮有效套路写回 skill / Profile（契约）

1. **在 `nexo-talk` 增加「抽象问题」小节**：先钉用语 → 多枪 retrieve → 噪声则定向读卡 → 回答分 document/system。  
2. **在 `领域思维范式` 追加默认路径（待用户确认写入）**：分析宏观波动时先分 **脉冲 / 放大 / 相位**；先问融资层级与预期惯例，再归因为外生冲击。  
3. **涌现小节**：要求 3–5 个可命名假说 + 各挂至少一卡锚 + 明确「未写卡」；结束时用 skill 规定的轻问捕获（已有，可写清触发词）。

### 6.3 回流：对话涌现 → 捕获/Buffer 的轻桥（产品）

1. 用户说「记一下」时，emerge 支持一次打包多个假说为 **link-hypothesis / claim nascent**。  
2. 或：talk 结束允许写入 `05-Buffer/scratch` 一条「对话涌现备忘」（仍非 Card），使 RAG 质料轨能搜到——需评估是否违反「分析留对话」；更稳妥是 **仅用户确认后** 进 Buffer。

### 6.4 库存：补元概念与危机形态（内容）

1. 一张「古典三义」总览 conflict/claim。  
2. 合法获取后编译 Kindleberger/R&R；先编译 Inbox 内 DD 簇，补「流动性幻觉」的微观机制。  
3. 给 `经济不稳定根源之争` 增加指向「稳定器反噬」「时滞相位」的 relates/extends，使检索子图更贴「三时钟」综合。

### 6.5 工具编排：减少旁路扫全库

　　定向 Python 扫卡有效但粗。可考虑：

- `retrieve --ids 经济不稳定根源之争,内生金融不稳定说,...` 强制种子；或  
- `retrieve --domain 金融权力投机与内生不稳定 --mode talk`  

　　让 Agent 少写一次性爬卡脚本，多走官方入口（便于评测与回归）。

### 6.6 OutBox 可发现性

　　过程复盘进 `04-OutBox/` 后，talk 默认不检索 OutBox。若希望「上次复盘改进是否生效」可被思维体看见，可考虑：索引可选纳入 OutBox 标题层，或在 STM 化石摘要里留一指针。

## 7. 本轮提示词组合的可复用清单（给后续 Agent）

　　面对「基于知识库深思 + 尝试涌现」类问题，建议固定组合：

1. Read `nexo-talk` + 扫一眼 Profile 相关节。  
2. `memory status`；必要时 `start`；`update` focus/tension。  
3. `retrieve` 第一枪：用户关键词 + 已知机制同义词。  
4. 读 context：列出 seeds；**显式丢弃**低相关高热卡。  
5. 若 core 不足：第二枪用卡名；或 `retrieve` 加 domain 约束（若 CLI 支持）/ 定向读 5–15 张枢纽卡。  
6. 回答：先 document 支架，再 system 涌现；每条涌现挂卡锚；问是否捕获。  
7. 过程债写入 `04-OutBox/`（本文类），结构债走 emerge/digest/construct。

## 8. 验收标准（若实施 §6）

| 项 | 现在（本轮观察） | 目标 |
|----|------------------|------|
| 不稳根源类 query 的 top seeds | 常混 1–3 个微观跑题枢纽 | 前 5 seeds 中跑题 ≤0–1 |
| 深思是否必须旁路扫卡 | 是 | 冲突/主张类深思 80% 可只靠 package |
| 涌现假说下轮可检索 | 否 | 用户确认捕获后可 retrieve 到 |
| Profile 是否改变分析顺序 | 弱 | 波动问题默认出现脉冲/放大/相位提问 |
