# 建构工具反馈与改进建议（本轮实操）

> 日期：2026-08-01  
> 性质：过程反馈与设计建议（非 Card；默认不作已定结论）  
> 场景：对约 63→69 张 Card 做建构；主动作 = `cluster` 拆过载 domain + 重挂归属；辅动作 = `distinguish` 修复人力资本 conflict 的 involves  
> 终态：domain ×5；validate 0 error / 0 warning  
> 关联：`nexo-construct`；`04-OutBox/2026-08-01-单domain过载-工程与提示词改进.md`

---

## 1. 一句话总评

　　建构工具链在 **「发现局部结构债 + 单镜执行 + 事务写入」** 上是可用的；对本轮真正关键的问题（假/过载 domain、domains 漂移）**诊断排序偏了**，**确定性信号几乎没点名**，主要靠 Agent 结合先验设计判断选用 `cluster` 才做对。工具有用，但默认建议顺序会把注意力引向噪声枢纽升格，而不是领域分裂。

---

## 2. 各类型工具：职责、本轮表现、建议

### 2.1 诊断入口：`construct`（默认 / `--diagnose`）

| 项 | 说明 |
|---|---|
| **设计职责** | 通盘扫描图与目录，产出报告与行动单，不直接改库 |
| **本轮产出** | `lenses-report.md`、`structure-ops-draft.md`、`structure-ops-llm.yaml`、`structure-seed-links.yaml`；未见独立的 `suggested-lenses.txt` |
| **有用之处** | 一屏看到「卡片数、全库目录、Buffer 索引规模」；行动单把 seed-links / involves / 枢纽候选拆开，便于人工分镜 |
| **不足** | ① 未把「全库仅 1 domain + 全员挂靠」标成一等告警；② 建议镜头顺序把 `cluster` 放在最后，与过载 domain 的优先序相反；③ `lenses-report.md` 体量过大（目录+Buffer 索引），不利于快速决策 |
| **建议** | 诊断摘要首屏增加：`domain_count`、每 domain 挂靠数、`domain_overloaded` 阈值；建议顺序改为 **cluster（若过载/假 domain）→ distinguish → articulate → cross_source**；报告分「摘要 / 行动单 / 全量附录」三层 |

### 2.2 确定性补边：`structure-seed-links` / `--apply-seed-links`

| 项 | 说明 |
|---|---|
| **设计职责** | 无 LLM：空 `relations` 的实例卡 → `applies-to` 所属 domain |
| **本轮表现** | **0 writes**（库内几乎没有「空边」卡） |
| **有用之处** | 定义清晰、可安全自动执行；Skill 正确强调「勿当完成态」 |
| **不足** | 对本轮主病（边太多、挂错域）**零贡献**；过载 hub 上已有大量 applies-to，seed-links 帮不上忙 |
| **建议** | 保留；另增对称的确定性检查：`applies-to` 指向非所属 domain、或单 domain relations>12 时输出 `hub_overlink` 信号（只告警，不自动删边） |

### 2.3 行动单：`structure-ops-draft.md`

| 项 | 说明 |
|---|---|
| **设计职责** | 把图分析与启发式变成可读、可勾选的步骤 |
| **本轮表现** | §0 seed-links 空；§1 distinguish involves 报「无」；§2 articulate 列出 12 个术语升格；§4 建议顺序偏 articulate 优先 |
| **有用之处** | 一眼看到「没有空边可补」「没有缺 involves 的 conflict」（按当时启发式） |
| **不足** | ① 「无待补 involves」**漏检语义错误**：`人力资本与信号论之争` 虽有 involves，但指向 method 工具卡而非两造 claim——行动单只查「有没有」，不查「合不合适」；② articulate 候选充满停用词（经济/市场/之争） |
| **建议** | involves 健康度：至少 2 个 target，且类型 ∈ {claim, model}，conflict 自身不算；术语升格加停用词表与最短词长；行动单顶部增加 **cluster 专节**（假 domain / 挂靠漂移） |

### 2.4 镜头：`cluster`

| 项 | 说明 |
|---|---|
| **设计职责** | 假 domain、空壳领域、孤儿、domains 漂移、近义合并 → 归属调整 / superseded |
| **本轮表现** | **主镜头，实质生效**：新建 4 sibling domain、收窄原 domain、重挂约 62 张实例；validate 通过 |
| **有用之处** | Prompt 职责与过载问题对齐；`--lens cluster` 生成的 prompt 明确「调整归属」优先序 |
| **不足** | ① Harness **不自动生成**「按主题重挂 domains」的 deterministic batch，大规模重挂需 Agent/脚本拼 `write --batch`；② 诊断未强制建议先跑 cluster；③ apply 时若未声明 `consumed_buffers`，仍可能大面积把 digested Buffer 标成 constructed（本轮 cluster apply 曾 Marked 247）——语义上「结构重挂」≠「消费了这些 Buffer」 |
| **建议** | 增加 `domain_rehome` 辅助：输入 mapping YAML → 生成合规 batch（保留 body/sources，只改 domains/relations）；constructed 标记仅当 `consumed_buffers` 非空或显式 `--mark-buffers`；诊断在 `domain_count==1 && cards>N` 时 **强制建议 cluster 第一** |

### 2.5 镜头：`distinguish`

| 项 | 说明 |
|---|---|
| **设计职责** | 张力显化：缺 conflict、缺 involves、主张 vs 可外核事实 |
| **本轮表现** | 行动单报「无」；人工复核后仍发现 involves **类型错配**；补建两造 claim 并改挂，镜头价值兑现 |
| **有用之处** | Prompt 与 ontology（involves 仅 conflict）一致；适合做张力结构的「质检」 |
| **不足** | 确定性信号过弱（有 involves 即过关）；未扫描「involves 指向 method/entity/domain」 |
| **建议** | 确定性规则：`involves` target 的 type ∉ {claim, model} → 列入 distinguish 信号；conflict 的 involves 数 ∉ [2,4] → warning；与「无 involves」分列 |

### 2.6 镜头：`articulate`

| 项 | 说明 |
|---|---|
| **设计职责** | 关系团抽 model/method、entity 枢纽、补 based-on/supports；少建碎 claim |
| **本轮表现** | **未执行**；诊断阶段的「枢纽概念候选 ×12」即 articulate 启发式预告，噪声高 |
| **有用之处** | 在 domain 已拆好、标题术语更「机制化」之后，可能有用（如「无谓损失」「价格歧视」真枢纽） |
| **不足** | 同 domain 内对标题切词取高频，必出「经济」「市场」「之争」；在 **单过载 domain** 上跑，噪声放大到不可用 |
| **建议** | ① 停用词 + 词长≥2 且非纯功能字；② **按 domain 分组** 统计高频词；③ 候选须同时满足：出现在 ≥3 张卡 **且** 无同名 model/entity **且** 不是 conflict 标题后缀；④ 建议顺序放在 cluster/distinguish 之后（拆域后再 articulate） |

### 2.7 镜头：`cross_source`

| 项 | 说明 |
|---|---|
| **设计职责** | 多源互补/对立 → 跨源边、conflict、问题清单 |
| **本轮表现** | **未跑**（本库同源教材为主，优先结构债而非跨源） |
| **建议** | 保持按需；教材单源库可降权；多报告/多作者库再作为默认后段镜头 |

### 2.8 镜头 Prompt：`construct --lens …` → `prompt.md`

| 项 | 说明 |
|---|---|
| **设计职责** | 给 LLM 单镜上下文：信号、目录、深读卡、Buffer 摘录、写入纪律 |
| **本轮表现** | cluster/distinguish 均能生成；深读卡在拆域后能带上新 domain，有帮助 |
| **不足** | cluster 信号栏常为「无额外信号」，把最重的工作完全推给模型通读目录；深读规模有限时，**看不到**全部待重挂卡 |
| **建议** | cluster 模式注入结构化信号：`domain_member_counts`、`cards_with_only_domain_X`、建议 split 草案（可空）；或支持 `--rehome-map` 文件路径写入 prompt |

### 2.9 写入闸门：`construct --apply` / `write --batch`

| 项 | 说明 |
|---|---|
| **设计职责** | 事务写入、校验、Journal、索引；construct apply 可标记 Buffer constructed |
| **本轮表现** | 两次 apply 均成功；拆域后 validate 干净；distinguish 仅 Marked 0 buffer（更合理） |
| **不足** | cluster 大批重写时 Marked 247 digested→constructed，易造成「质料已被结构消费」的错误印象；全量重写 body 的 batch 体积大，依赖脚本生成尚可，纯手写不可扩展 |
| **建议** | Buffer 状态迁移与结构-only batch 解耦；可选 `operation.structure_only: true` 跳过 buffer 标记；提供官方 `construct rehome` 子命令生成 batch |

### 2.10 图分析其它 ops / `structure-ops-llm.yaml`

| 项 | 说明 |
|---|---|
| **本轮表现** | 行动单写「图分析其它 ops：0」；机器可读 yaml 存在但未驱动本轮决策 |
| **建议** | 若 LLM ops 与 draft 重复，合并为单一真源；或让 draft 明确「本轮采纳/忽略」勾选，避免双文件漂移 |

### 2.11 Skill / 规程：`nexo-construct`

| 项 | 说明 |
|---|---|
| **有用之处** | 单镜禁止 `all`、seed-links 非完成态、原则上少新建——约束正确 |
| **不足** | 「与用户确认镜头」与「用户说建构即授权」边界清楚，但 **默认建议顺序** 写在行动单里且偏 articulate，Agent 若盲从会做错题 |
| **建议** | Skill Workflows 写明：诊断后先读行动单 **§cluster/过载信号**；有 `domain_overloaded` 时不得先 articulate；破例新建 domain/两造 claim 须在 operation.note 解释（本轮已遵守） |

## 3. 工具协同图（本轮实际 vs 理想）

**本轮实际**

```text
diagnose →（行动单暗示 distinguish/articulate 优先）
       ↘ Agent 覆盖判断 → cluster（脚本生成重挂 batch）→ apply
                         → distinguish（修 involves）→ apply
```

**建议默认**

```text
diagnose
  → 若 domain 过载/假 domain → cluster（必要时 rehome 工具）
  → distinguish（involves 存在性 + 类型合法性）
  → articulate（按 domain 分组、停用词过滤后的枢纽）
  → 按需 cross_source
  → seed-links 仅补真·空边
```

## 4. 按优先级的改进清单

| 优先级 | 改动 | 主要消除的摩擦 |
|---|---|---|
| P0 | 诊断摘要：`domain_count` + 挂靠分布 + `domain_overloaded`；建议顺序 cluster 优先 | 盲从 articulate |
| P0 | involves 类型合法性信号（须 claim/model） | 「有 involves 却结构错」漏检 |
| P1 | articulate 停用词 + 按 domain 分组高频词 | 噪声枢纽候选 |
| P1 | `structure_only` / 重挂不批量 mark constructed | Buffer 状态语义污染 |
| P2 | 官方 rehome mapping → batch 生成 | 大规模归属调整不靠临时脚本 |
| P2 | lenses-report 分层（摘要 / 行动 / 附录） | 报告不可读 |
| P3 | hub_overlink 告警；cross_source 在单源库降权 | 边膨胀与镜头浪费 |

## 5. 对本轮建构质量的反馈（工具视角）

　　**成功不在工具自动做对，而在工具提供了可执行的单镜写入通道，且校验挡住了坏图。** 过载 domain 的识别主要来自前期复盘与设计文档，而非本次 diagnose 的醒目信号——这说明 Harness 的「结构债类型覆盖」仍偏 **边/involves/空壳**，偏弱于 **领域粒度**。  

　　`cluster` 作为镜头 **名实相符、本轮关键**；`articulate` 自动建议在拆域前 **应默认降权或折叠**；`distinguish` 需要从「有无 involves」升级到「involves 是否像对立双方」。  

　　seed-links 保持小而正确即可，不要扩张成「结构完成」的错觉。

---

## 6. 结语

　　建构工具适合做 **有闸门的结构手术**，不适合做 **无信号的自动升格**。下一步工程重点应是：让诊断把「假 domain / 挂靠漂移 / involves 类型」变成一等公民信号，并让 `cluster` 在过载场景下成为默认第一镜——这样 Agent 少靠先验「蒙对」，工具链才与 AGENTS 里「Harness 管过程、LLM 管语义」的分工一致。
