本轮（第09–12章编译 → 140 片 Buffer 消化 → 库内约 36 卡）里，真正伤到**最终卡片质量**的，不只是偶发 apply 失败，而是几条会系统性塑造「卡长什么样」的链路。

## 问题如何传导到卡片质量

### 1. 分波选题：tension 先于机制

　　digest 默认常先捞 tension。空库或新主题刚进库时，冲突卡/领域「内在张力」先堆起来，而四类物品、矫正税、科斯、贸易福利等**解释骨架**后到。结果是：对立写得很满，机制卡后补；domain 变成张力仓库，实例卡之间关系稀、可复用模型偏晚。

### 2. 「建议新建 ≤N」压出两种假节约

　　为压新建数，常见两种做法，都会伤质量：

- 把本该独立的模型**糊进 domain 内在张力**（可检索、可 involves 变差）；
- 或反过来在额度内**一次塞满 conflict + 两造 claim**，正文偏薄、摘录重复。

　　本轮医疗政府角色、产业政策、贸易补偿等结构单元成立，但部分卡「结构齐、质料薄」。

### 3. enrich 累积：sources 膨胀、正文叠床架屋

　　多波 enrich 同一枢纽（domain、弹性、贸易、外部性）时，sources 易破 12，正文靠追加段落变长，而不是重写为更干净的机制叙述。终局卡能用，但**单卡可读性与「一事一意」**下降，construct 成本前移到 digest。

### 4. YAML / id 硬故障打断聚合节奏

　　已踩过的坑会间接伤质量：

| 故障 | 质量后果 |
|---|---|
| `sources` 含 `:` 未加引号 | apply 整批回滚 → 同波机制被拆到后波，聚合被撕开 |
| 卡片 id 含全角「：」 | 新模型卡当波落空（如外部性内部化曾失败） |
| 文件名 `%` 进 `strftime` | Buffer 丢失/重跑，编译质料不齐 |

　　质料不齐时，digest 只能用残缺簇建卡，槽位易空或靠套话补。

### 5. 编译体裁与章序

　　单章被判 `essay`、默认按字数而非章序开编，本身不直接写坏卡；但若未暂存筛选，短章乱序进库，digest 会在**缺上游模型**时先消化下游应用（如贸易分配 tension 早于福利模型），加重第 1 点。

### 6. 一域吞四章

　　「市场效率与政策干预」扛了弹性–管制–税收–公共品–外部性–贸易–医疗。边界清楚时是优点；过载时领域肖像与张力列表变目录，**聚类信号变弱**，后续 retrieve「从哪张卡出发」变糊。

## 以卡片质量为目标的优化建议

### A. 消化编排（优先、不改本体类型也能做）

1. **Bootstrap / 新主题波次：meaning-unit 优先，tension 封顶**  
   首波或新问题域先建 domain + 1～2 个核心 model，再消化 tension；plan 可提示「conflict 候选缺同主题 model」。

2. **新建预算改「结构单元」**  
   计分：一个 model = 1；一个 conflict bundle（conflict+两造）= 1；不要按裸卡张数压。鼓励「少而厚」而非「少而糊进 domain」。

3. **enrich 纪律写进 prompt**  
   - sources：每波重写压缩表（教材总述 + ≤若干代表性 Buffer），禁止无限 append；  
   - 正文：enrich = 改机制段，不在文末叠「又及」；超长则拆出新卡或留给 construct。

4. **domain 扩边界的闸门**  
   新章若核心问题变了（国际贸易分配、医疗保险失灵），优先**新 domain 或子域 claim/model 挂 domains**，而不是只往同一张领域卡塞张力。例如可评估拆出「市场失灵与产权」「开放贸易与保护」——以检索与教学一致性为准，而非为拆而拆。

### B. Harness 闸门（直接减少残缺质料）

5. **lint batch**：`sources[]` 必须为 str；card `id` 禁止 `：`/`:` 等非 `[汉字A-Za-z0-9-]` 字符；失败给出行号。  
6. **`self_check` 与 `write` 对齐**（含 `profile_field`），避免「自检红、写入绿」或反过来。  
7. **compile 文件名**：时间戳与标题分离（`%` 问题已修）；digest skill 写明 response 必须 `batch-XXX-<genre>-response.md`。

### C. 编译质料标准（上游决定下游卡能否厚）

8. **宁少而厚的 Buffer**：机制 + 条件/数字 + 边界 + 短摘录；习题窗提炼可迁移机制，避免「题号清单」。  
9. **章内多波完成后再 digest 该章簇**（或按主题打包波次），减少「半章 tension + 半章机制」交错消化。

### D. 质量验收（digest 末、construct 前）

10. **每张新/大改卡自检四问**：无读过原书能否 grasp？依据是否机制而非标题回声？失效边界是否具体？relations 是否指向真实对象而非只堆在 domain？  
11. **construct 优先镜头**：compact-sources、drain-domain-dump、合并同构弹性/贸易叙述、为仍挤在 domain 张力里的对立补 conflict。

## 建议落地顺序（投入 / 质量收益）

| 优先级 | 动作 | 主要提升 |
|---|---|---|
| P0 | batch lint（sources 类型 + id 字符） | 少回滚、机制同波落盘 |
| P0 | 新主题波次 meaning-unit 优先 | 骨架先于对立 |
| P1 | enrich 压缩 sources + 禁叠床架屋 | 单卡可读 |
| P1 | 新建预算改结构单元 | 少空壳、少 domain 倾倒 |
| P2 | 评估是否拆 domain / construct 清仓 | 长期检索与复用 |

　　一句话：卡片质量瓶颈不在「写得不够像教材」，而在**消化顺序、聚合粒度、enrich 卫生**；把这三件事闸住，终局卡会更薄、更可挂、更可判。若需要，我可以把上述内容落成 `04-OutBox` 复盘文档，或直接改 digest skill / `self_check` 的 P0 项。

【新硬故障】非法关系类型 relates-to
　　Wave05 apply 直接失败：'relates-to' is not a valid RelationType。契约只允许 extends / supports / conflicts-with / involves / example-of / applies-to / based-on / influences，子代理发明了近义词。

　　与旧的「sources 冒号」同类：自检未拦、写入才炸。本轮靠手工替换后才落盘。防呆应对齐：self_check / lint 校验 relations[].type 枚举，并在 digest prompt 里写死合法集合（本轮后半已口头约束）。

2. 【加剧】单卡「章级百科」膨胀

　　旧问题是 sources>12 warning；本轮新形态是 body 本身过载，且 conflict 卡被塞进税制结构/VAT/CBO 等「模型事实」，冲突定位被稀释。construct 缺席时，这笔债会继续滚。

3. 【加剧】单一 domain 成万用枢纽
　　54 张卡仍几乎全部挂在「市场效率与政策干预」；domain 的 relations 已扩到约 11 条（成本、竞争供给、垄断三件套、税制冲突等）。第13–16章实质是产业组织 / 企业决策新层，却没有拆第二 domain 或升枢纽——消化纪律「domains 必须含既有 domain」在操作上被理解成「只许这一个」，骨架错位加剧。

4. 【编排】张力优先 + 跨章混波
　　首波同时抽到：成本张力、税制 VAT/横向公平、垄断价格歧视、反垄断 Bork–Khan——四章主题挤进同一批，先建薄壳再靠后续 meaning-unit 回填。能跑通，但易造成：过早 conflict/model、后波只能巨型 enrich。旧复盘谈过「空库 tension 优先」；库已非空后，跨主题混抽仍是新摩擦源。

5. 【编译侧轻问题】窗内块数上限偏软
　　Harness 说每窗 1–6，但本轮出现过单文件 7–8 块、复习题窗偏碎；--check-responses 仍 OK。质量风险是 Buffer 变薄片，消化时更难「宁聚合」。

　　另：有一波 apply 报 consumed 15/16（路径匹配漏一片），属偶发，但说明 consumed_buffers 与磁盘名仍可能错位。

6. 【缺口】Profile / construct 几乎缺席
　　第01–04 消化还写过思维范式；第13–16 约 180 片 Buffer、11 波消化，几乎无 profile_field。领域级范式（如「会计利润≠经济利润」「P=MC 效率基准」「反垄断标准之争」）本可沉淀，却全堆在 Card 正文里。

　　消化清空后未做 construct：合并平行垄断卡、压缩 sources、拆 domain——结构性问题原样留下。
