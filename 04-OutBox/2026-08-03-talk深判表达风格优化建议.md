## 1. 一句话结论

　　分析讨论（talk / 深判）面向用户时，应优先交付**可读的推理过程**，而不是把知识库卡片 id、冲突名与术语做成「拼接摘要」。库内专名可以保留，但必须嵌在完整句子与因果链里；表格只作辅助，不能代替「他在说什么 → 为何这样推 → 卡在哪里」。

---

## 2. 问题是怎么暴露的

　　首轮对公开言论的「知识库对接」回复出现了典型失效模式：

1. **术语堆叠**：在短句里连续抛出相对定价、坏时期、左尾、联合假说、融资螺旋等标签，读者必须自行补全中间推理。  
2. **过程被压缩成对照表**：表能列「主张 / 对接卡」，却跳过「为何能对接、对接后推出什么、哪里推不下去」。  
3. **评判过早收束成口号**：例如「解释层强、决策层未闭环」——方向对，但若前面没有用人话走完冲突，读者只会感到被下了判词。

　　用户改写要求之后，第二轮采用「材料边界 → 拆成几件可分开想的事 → 逐步推演 → 再定位」的结构后，反馈为：**这才是分析讨论需要的表达风格**。

　　由此得到设计信号：问题不在「是否引用知识库」，而在**引用知识库时是否仍把人当需要被说服、需要跟着推的对话者**。

---

## 3. 目标风格（讨论时应遵守）

### 3.1 必须有的骨架

对复杂公开主张或争议问题，默认按下列顺序展开（可裁剪，不可颠倒成「先堆术语再补故事」）：

1. **材料边界**：评什么、不评什么（尤其禁止事后结果反推时，开篇钉死）。  
2. **拆题**：把缠在一起的主张拆成几件可单独成立或单独失败的事。  
3. **逐步推演**：对每一件写「若接受 → 推出什么 → 还缺哪一问」。  
4. **并置冲突**：若几件事对同一前提要求相反，用人话写清冲突，再给表（可选）。  
5. **定位式评判**：说明「若接受 A 须承担什么；若接受 B 须解释什么」——定位而非替用户下单或用结果打分。

### 3.2 句子与术语纪律

- **先人话，后专名**：先说清机制，再括注或链到卡片（如「便宜借钱买更会生钱的东西（套息）」）。  
- **专名出现时必须带一句作用**：不只写卡名，而写「这张卡提醒我们问的是哪一个问题」。  
- **禁止无动词的术语串**：避免「SDF/相对定价/坏时期分轨/融资脆弱同族」这类读者无法跟读的压缩句。  
- **比喻可用，但只服务一步推理**：例如「捡硬币 vs 压路机」只说明平静期与坏时期不对称，不另开术语丛。  
- **表格是附录不是正文**：表总结已经讲过的拆分；正文须已能独立读懂。

### 3.3 与写卡风格的分界

| | 卡片 / Buffer | 分析讨论（talk / 深判） |
|---|---|---|
| 读者 | 未来检索与建构 | 当前对话中的人 |
| 密度 | 可高，专名可密 | 推理链优先，专名稀释 |
| 成功标准 | 可独立复用、可挂边 | 用户能复述因果与张力 |
| 引用 | id / 路径即可 | 引用后必须用人话接上「所以呢」 |

　　同一知识体，两套外显：入库求结构；对话求可跟读。不可把 construct/digest 的压缩句法直接端到用户面前。

## 4. 优化建议（可落地）

### 4.1 提示词 / 技能侧（优先）

1. 在 `nexo-talk` / `nexo-judge` 的 Invariants 或 Anti-patterns 中增加一条显式纪律：  
   **分析讨论禁止「术语拼接摘要」作为主交付；须含拆题与逐步推演。**  
2. 在 judge 工作流「综合」步骤旁加检查句：  
   **若删去所有卡片 id 与英文缩写，用户是否仍能复述结论依据？** 不能则重写。  
3. 对「用知识库评析外部言论」类任务，默认采用上文 §3.1 五段骨架（可写入 talk 的可选 checklist，而非加长空泛系统提示）。

### 4.2 Agent 行为侧（立即生效、无需改代码）

1. 第一稿若偏「卡名对照表」，在发出前自检：每条对照是否至少有一句「推出了什么 / 推不下去在哪」。  
2. 用户一旦反馈「听不懂 / 太碎」，优先整段重写推理，不追加更多术语解释。  
3. 深判透镜不超过 3–4 个时，每个透镜用**一段连贯叙述**，避免透镜标题下再堆子弹列表。

### 4.3 可选工程侧（有证据再做）

1. talk/judge 的 Context Package 渲染：对用户可见回复**不默认罗列**全部 seed id；改为「正文引用处再出现」。  
2. 若未来做回复质量闸门：对用户可见长答检测「卡片 id 密度 / 连续专名串」仅作警告，不自动改写（改写权仍在对话模型）。

　　复杂度门槛：目前摩擦已由用户一句话钉死；§4.1–4.2 为最小改动。§4.3 仅在同类投诉重复出现时再立项。

## 5. 正例与反例（压缩）

**反例（应避免）**  
　　「A+B 接相对定价与坏时期左尾，C 接状态依赖 m，与明斯基融资脆弱同族，故解释层强、决策层未闭环。」

**正例（讨论时应靠近）**  
　　「他把买商社改写成买海外资产的容器——题目从『日本景不景气』变成『这些资产会不会持续分红』。同时又说低息套息还在，又说三五年体制可能变。低息套息要靠便宜融资继续；体制变往往意味着融资不再便宜。两件事可以时间错开，但必须说明转换临近时先减哪一条腿。公开表述没有给出这条切换规则，所以它更像换角度看问题的框架，还不是可执行的仓位规则。」
