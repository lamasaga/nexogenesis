## 3. 最后一次建构：问题特写

### 3.1 诊断「全绿」掩盖语义错配（P0）

**现象**

　　`structure-ops-draft.md` 写明：

- 待补 involves 的 conflict：**0**  
- 图分析遗留：（无）  
- 建议顺序仍把精力导向 articulate 的 12 个术语升格  

　　人工复核却发现：`主动稳定化与时滞之争` 正文对立双方是「主动稳定化 vs 时滞反对派」，`involves` 却指向三个 **model**（财政乘数、流动性偏好、美联储工具）。这与更早的「人力资本 conflict involves 指到 method」是同一类病：**有边 ≠ 两造钉对**。

**根因**

1. 确定性检查只测「conflict 是否至少有 N 条 involves」，不测 target 的 `type`、不测是否覆盖正文「对立双方」。  
2. digest 建 conflict 时，为省新建额度，常直接 `involves` 已有机制卡，把「解释工具」当成「立场双方」。  
3. 行动单建议顺序仍是 seed-links → distinguish → **articulate**，在 involves「形式上齐全」时，distinguish 被标成空操作，agent 若盲从顺序会去做噪声升格。

**本轮处置**

　　跳过 articulate；跑 distinguish：新建两造 claim，involves 改钉 claim；原 model 降为 based-on/influences；补 `短期波动与AD-AS → 开放经济双市场模型` 跨域边。validate 通过。

**设计含义**

　　上次反馈已写「involves 健康度」，**本轮再次复现且升级**：对象从 method 变成「多个相关 model」。若仍不落地规则，每消化一章政策争论都会重复「诊断说没事 → agent 人工发现 → 再 distinguish」。

### 3.2 articulate 噪声不但未减，还出现「切词碎片」（P0）

**现象（本轮行动单原文级别）**

| 候选术语 | 问题 |
|----------|------|
| 垄断 / 定价 / 市场 / 储蓄 / 失业 / 度量 | 标题高频词，已有完整 model 簇，升 entity 无增量 |
| 医疗 / 政府角色 / **医疗政府** / **疗政府角** | 同一簇标题被切成碎片；「疗政府角」近乎乱码候选 |
| 工会 / 工资 | 刚修好的 conflict 簇，再升格是重复枢纽 |

　　`lenses-report.md` 仍达数十万字符（全库目录 + Buffer 索引），不利于「先看摘要再决策」。

**根因（相对 8-01 反馈：未改）**

　　按标题切词 + 同域共现计数，无停用词、无最短有效词、无「已有同名/近义 model 则抑制」、无 n-gram 完整性约束。domain 变多后，噪声从「全书一个 hub」变成「每个 domain 一撮停用词」。

### 3.3 建议镜头顺序与真实债仍错位（P1）

　　行动单 §4 仍推荐：seed-links → distinguish → articulate → 按需 cluster。  
　　本轮真实优先序应是：**distinguish（语义 involves）→ 按需跨域补边 → 明确跳过 articulate**；cluster 因无新过载阈值未触发。  
　　与 8-01 建议的「过载则 cluster 第一」不矛盾——关键是诊断**没有输出「本轮真实优先镜头」**，只输出固定模板顺序。

### 3.4 seed-links 连续 0 贡献（P2，已知）

　　空边挂 domain 对本库已无增量；却仍占建议顺序第 1 步，挤占注意力。应改为：有 writes 才出现在行动单顶部，否则折叠为一行「seed-links: 0（跳过）」。

## 4. 近期其它阶段新发现 / 仍未消除的摩擦

### 4.1 Digest：conflict 偏好「involves → model」（与建构债同源）

　　第29–36章消化新建了多张 conflict（工会、主动稳定化、有效市场等）。其中部分波次为控制「新建 ≤4」，把乙方立场挤进已有 model，或只建甲方 claim。结果是：digest 报告「有 conflict」，construct 才发现两造不对称。

**建议（digest 契约）**

- 新建 conflict 的硬条件：同批或已有 **≥2** 个可 involves 的 claim/model；优先 claim–claim。  
- prompt / 自检：`involves` target 若全是 model 且正文有明确「甲方/乙方立场」→ warning：`conflict_involves_stance_gap`。  
- 质量提示「新建 ≤N」应对 **conflict 结构** 单独开预算（例如允许 +2 claim 专供两造），避免用机制卡顶替立场卡。

### 4.2 Digest：domain 增生 vs 过载——钟摆另一侧

　　过载反馈生效后，宏观段顺利新建了度量、增长、金融、失业、货币、开放、短期波动、医疗等 sibling domain，导航性明显改善。新风险是：

- Agent 提示里「宜新建 domain」略强时，**边界相近**的域（如货币制度 vs 货币增长、开放基础 vs 双市场）依赖人工判断；  
- domain 卡 `relations` 与实例卡双向 applies-to 仍易超 12 → 仅 WARNING，无「域内成员数」摘要进 digest plan。

**建议**

- digest `--plan` 首屏增加：`domain_count`、各域成员数、本波主题命中域。  
- 新建 domain 判定写成可勾选：新问题层级 / 不可被现有域诠释覆盖 / 预计 ≥3 张实例；否则 enrich 最近域。

### 4.3 Digest / enrich：sources 膨胀仍在（已知未根治）

　　validate 仍对 `GDP支出四分法恒等式`、`医疗保险道德风险与逆向选择` 报 sources>12。多波 enrich 整卡替换时习惯「追加不归档」，与 8-01 复盘相同。

**建议**

- enrich 规程：sources 保留「原文章锚点 ≤K + Buffer 路径代表 ≤M」；旧 Buffer 路径进正文「质料沿革」或 Journal，不无限堆 frontmatter。  
- 超限时自检 warning 升级为 digest `--strict` 可选项。

### 4.4 Compile：规模成本（非正确性）

　　第34章等长文多波（约 3 波/章）、四章一轮约 10–12 波 response；依赖子代理串行，墙钟时间显著。命名与归档已稳定。

**建议**

- 保持 `-essay-response` 铁律与「少 prompt 波次删旧 response」检查清单（可写入 skill 显性步骤）。  
- 可选：`--wave-prompts` 与章末窗合并策略的文档化，减少「最后一波只剩 1 prompt」的目录清理负担。

### 4.5 编排层：子代理授权与复述成本

　　用户一句「消化/建构」后，父代理用长 prompt 复述五域/硬规则/历史教训；卡库越大，遗漏风险越高（例如忘记禁止全角冒号 id、忘记 sources 引号）。

**建议**

- 将「digest/construct 铁律」收成 `.agent/reference/` 或 skill 内 **可 `@` 的短清单**（YAML 引号、involves 健康度、domain 新建判定、禁止 articulate 停用词），子代理 prompt 只引用路径 + 本波特例。  
- construct 子代理默认指令改为：**先读行动单摘要，再人工核对 conflict involves 类型；行动单说「无」不得直接跳过 distinguish。**

## 6. 设计思路（原则层）

1. **形式完备 ≠ 语义完备**  
　　有 `involves`、有 conflict 卡、有 domain 挂靠，只说明通过了「链接存在性」闸门。社科知识体需要的是「对立可指认、机制可归属、领域可导航」。确定性规则应逼近语义完备的**可机检子集**（类型、数量、对称性），其余仍交 LLM——但诊断不能宣称「无事」。

2. **诊断应输出「本轮禁止做什么」**  
　　对噪声 articulate、0 seed-links、无过载 cluster，应显式写「跳过」；否则建议列表本身变成待办压力。

3. **digest 与 construct 的接口要更硬**  
　　digest 负责对象涌现；construct 负责组织。若 digest 允许「无两造的 conflict」，construct 就会永不#if 地做补丁。把两造预算前移，比事后升格更便宜。

4. **过载与碎片化是同一光谱的两端**  
　　8-01 治单 domain 过载；8-02 要防标题切词升格与域边界过碎。闸门应对称：成员数过大拆域；候选枢纽过碎则抑制升格。

5. **Agent 工作流以「证据优先于模板顺序」**  
　　最后一次建构的有效路径是：读行动单 → **不信任「involves=0」** → 抽查最新宏观 conflict → distinguish。应把该路径写成默认，而不是例外聪明。
