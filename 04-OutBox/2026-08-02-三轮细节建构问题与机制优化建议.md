## 1. 一句话结论

　　三轮都能把结构债做干净，但**有效路径几乎全靠 Agent 人工诊断 + 手写/脚本拼 batch**；Harness 的「行动单 / 同域候选 / articulate 术语升格 / 固定镜头顺序」对这三轮主债**要么指错方向，要么给出不能用的候选，要么制造假待办**。真正起作用的确定性动作是：`seed-links`（在重挂后短暂有空边时）、`suggest_conflict_card`（直销 vs 寡头）、以及 Agent 自写的 stance_gap / 未挂网 Buffer 扫描。优化重点应是：**让诊断输出「可执行的正确对象」，而不是「形式上正确的检查清单」。**

---

## 2. 三轮各自做了什么（压缩）

| 轮次 | 用户意图 | 实质动作 | 工具实际贡献 |
|------|----------|----------|--------------|
| ① domain 涌现 | 新旧卡合域 | 3 枢纽 domain 升格 + 薄域 superseded + 约 85 张重挂；旧域补跨源衔接 | **诊断未提供「涌现方案」**；cluster/重挂 batch 基本由 Agent/子代理完成 |
| ② 张力梳理 | 枢纽区分 | seed-links×7；补空 involves；新建对立 claim；修 phenomenon/conflict 错挂；市政 covering conflict；Profile 张力条目 | 行动单点名「缺 involves」有用；**同域候选几乎全错**；articulate 仍噪声 |
| ③ tension 抽样 | 曼昆未挂网升格 | 13 条 Buffer：6 新 conflict + 对立 claim，其余 enrich 已有卡挂源；仍余 ~23 digested 未挂网 | **无专用命令**；「未挂网」靠自写脚本；`construct --apply` 标记 constructed 数量与 `consumed_buffers` 不完全一致 |

## 3. 遇到的问题（按严重度）

### 3.1 P0：`require_involves` 的「同域候选」机制基本无效

**现象（第②轮行动单原文级）**

　　缺 involves 的凡勃伦 conflict（体育 / 运气信仰 / 民族服饰）被正确点名，但「同域候选」列出的是：

- `中日材料战的管理-替代困境与供应链去耦合`
- `存储高价环境的AI需求与寡头供给管理共谋模型`
- `小院高墙作为获取性战略的解释模型`
- …

　　这些与体育 workmanship、运气信仰、服饰规范**毫无立场对应关系**，只是同挂在大域或共现域里的热门卡。若 Agent 盲从候选补 involves，会制造比「缺边」更糟的 **stance_gap**。

**根因**

　　候选生成 ≈「同 domain 下任意 claim/model」，没有：

- 与 conflict 正文「对立双方」的标题/措辞对齐；  
- 排除已是应用实例、跨题模型的卡；  
- 「无合适候选 → 建议新建两造 claim」的显式分支。

**处置**

　　忽略同域候选；从 conflict 正文与 sources 抽出立场，**新建 claim 再 involves**。与「原则上 construct 少新建」摩擦（见 3.5）。

---

### 3.2 P0：involves「有边」与「钉对类型」仍分裂；诊断漏检未升级

**现象（第②轮）**

| 错挂类型 | 例 | 行动单是否点名 |
|----------|----|----------------|
| involves → **phenomenon** | 印度金币流通之争、市场大趋势、Ambedkar 冲突 | 多数只报「缺 involves」或漏报 |
| involves → **另一张 conflict** | 管理-替代之争 → 市场大趋势之争 | 未报 stance_gap |
| involves 仅一侧 | 慈善、投行利益冲突、Ambedkar | 部分报缺，不报「不对称」 |
| **已 superseded** 仍报缺 involves | `1873年铸币法案民主合法性与作者归因争议` | **误报**（主冲突已拆出作者归因卡） |

　　第①轮涌现后图变干净，但类型错配债被带进第②轮；第②轮靠脚本扫 `involves target.type ∉ {claim,model,entity,method}` 才一次清零。

**与预期落差**

　　此前 OutBox 已建议 `stance_gap` 健康度；本三轮诊断**仍未落地**，继续只做「有没有 involves」。

---

### 3.3 P0：articulate 术语升格对三轮主债零贡献且持续噪声

**现象**

　　三轮均未采纳 articulate。行动单仍稳定输出 12 个「垄断 / 定价 / 市场 / 储蓄 / 医疗 / 政府角色 / 医疗政府 / **疗政府角** / 本位 / 制度 / 货币 / 印度」一类候选。

**为何无效**

- 主债是 domain 归属与 conflict 立场，不是缺 entity 名词卡；  
- 切词残片与停用词未滤；  
- 「已有完整 model 簇」无抑制。

**预期 vs 实际**

　　设计预期：关系团 → 升枢纽。  
　　实际：注意力税 + 降低对整份行动单的信任（「连这个都错，别的也要人工复核」）。

---

### 3.4 P1：固定镜头顺序与真实优先序持续错位

**模板顺序**（行动单 §4）：seed-links → distinguish → articulate → cluster  

**三轮真实优先序**

| 轮次 | 应优先 | 模板是否指向 |
|------|--------|--------------|
| ① | cluster / 自定义「域涌现+重挂」 | 否（无涌现方案输出） |
| ② | distinguish（语义 involves） | 部分（有缺 involves，但夹杂错误候选与 articulate） |
| ③ | distinguish / cross_source 抽样挂 tension | 否（tension 未升格淹没在超长 prompt 列表里，无「抽样策略」） |

　　seed-links 在第②轮**意外有用**（7 张空边，多因涌现/新建后 relations 为空），说明「永远跳过 seed-links」也不对——应对的是**按数量动态置顶**，不是写死第一或写死忽略。

---

### 3.5 P1：construct「少新建」与 distinguish「必须两造」制度冲突

**现象**

　　第②③轮要补齐 involves，库中经常**没有**对立 claim（凡勃伦三冲突、器官/租金/效率平等、安全带等）。不新建则无法合法 involves；新建则违反 skill「原则上不新建 Card」。

**实际做法**

　　在 operation.rationale 中声明「为 involves 结构必需」后新建立场 claim——有效，但**无 Harness 预算通道**（例如 `stance_claim_budget`），每次都靠 Agent 自觉。

**digest 接口债**

　　大量 tension Buffer 已 `digested`，语义进了 model 正文或单侧 claim，却未留下可 involves 的两造——第③轮变成「事后补建 conflict」，成本高于 digest 当时一次做对。

---

### 3.6 P1：tension「未挂网」探测脆弱；升格无一等公民命令

**现象（第③轮）**

- 用 `sources` 是否包含 Buffer 文件名判定「未挂网」：约 36 条 digested 未挂源；但其中不少**思想已进卡**（贸易补偿、人力资本、寡头合谋等），只是漏挂路径 → 「未挂网」高估结构空洞、低估语义覆盖。  
- 反过来：GDP 非法活动等已在 sources 中，探测为已挂网，但仍可能缺独立 conflict——「已挂网」≠「张力已升格」。  
- `construct --lens distinguish` prompt 把数十条 tension 未升格候选**整表倾倒**，无域名分层、无「与已有 conflict 标题相似度」、无抽样配额。  
- apply 日志：`Marked 22 buffer(s) constructed`，而 operation 显式 `consumed_buffers` 为 13 ——**标记范围与声明不完全一致**（与既有「cluster 误标大量 Buffer」同类）。

---

### 3.7 P2：domain 涌现无一等工具面

**现象（第①轮）**

　　涌现方案（三枢纽、薄域并入、跨源衔接）是语义工作，合理；但 Harness 不提供：

- 「按主题簇建议 merge/split domain」的可读草案；  
- `domain_rehome` mapping → 合规 batch 的辅助；  
- superseded domain 后自动检查成员 `domains[]` 是否仍指向旧 id。

　　结果：涌现质量依赖长上下文 Agent，**可重复性差**，且易与 validate 幽灵域/幽灵边问题耦合（此前新卡入库后的 ERROR 潮已验证）。

---

### 3.8 P2：仍有效的少数机制（避免全盘否定）

| 机制 | 本三轮作用 |
|------|------------|
| `validate` 事务闸门 | 每次 apply 后 ERROR=0，挡住幽灵边 |
| `suggest_conflict_card`（直销 conflicts-with 寡头） | 第②轮正确点名 → 建成 covering conflict |
| `apply-seed-links`（空边时） | 第②轮 7 张挂回 domain，降低「无 outgoing」噪声 |
| `write --batch` / `construct --apply` | 原子写入可靠 |
| Agent 自写 stance_gap / 未挂网扫描脚本 | 实际完成第②③轮主债的主工具 |

## 4. 没有实际产生作用的机制（清单）

1. **articulate 高频词 → entity/model 升格建议**（三轮采纳数 = 0）  
2. **involves「同域候选」列表**（凡勃伦题上候选与题意无关；不能当补边输入）  
3. **固定「seed → distinguish → articulate」建议序**（与三轮真实优先序不符；articulate 段为死权重）  
4. **对 superseded conflict 的 require_involves**（假待办）  
5. **巨型 `lenses-report.md`（全库目录+Buffer）**（三轮决策均改读行动单摘要 + 人工/脚本；报告本身不驱动动作）  
6. **distinguish prompt 内「tension 未升格」长列表**（无优先级时等于没列表；第③轮另写抽样逻辑）  
7. **「诊断说 involves 已齐 = 可跳过 distinguish」的隐含工作流**（第②轮若盲从会漏掉 phenomenon/conflict 错挂）

## 5. 与预期不符合的机制（清单）

| 机制 | 设计预期 | 本三轮实际 |
|------|----------|------------|
| seed-links | 过载库上常为 0、可忽略 | 域涌现/新建后会出现一批空边；**有数量时应置顶**，无数量时应折叠 |
| require_involves | 指出缺边 conflict 并给可用双方 | 缺边点名尚可；**候选不可用**；superseded 误报；类型错配不报 |
| construct 少新建 | 消化已建对象，建构只组织 | distinguish 常**必须新建**立场 claim，制度未开口子 |
| tension digested | 消化即进入可检索知识结构 | 大量仅 status=digested，**sources/conflict 未挂**；升格靠抽样人工 |
| consumed_buffers | 精确声明本批消费 | apply 侧 constructed 标记数可 **> 声明列表** |
| 同域共现 ≈ 相关 | 同域卡可作 involves 候选 | 大域（凡勃伦+管控应用混挂）下共现**不等于同争议** |
| 行动单「可执行」 | Agent 可按条目写 batch | 条目可执行度低，需改写为「建两造 + involves」自定义方案 |

## 6. 优化与修改建议

### 6.1 立刻可做（Harness / 诊断启发式）

| # | 改动 | 验收 |
|---|------|------|
| A | **involves 健康度**：≥2 条；target `type ∈ {claim, model}`（可选 entity/method 但标 `weak_stance`）；禁止 target 为 phenomenon/conflict/domain；两侧对称检查 | 第②轮五类错挂在诊断 §1 被点名 |
| B | **跳过 lifecycle≠active** 的 require_involves | 1873 superseded 不再出现 |
| C | **同域候选废除或降级**：改为 (1) 正文对立双方标题模糊匹配现有 claim；(2) 无命中 → 输出 `suggest_create_stance_claims: [甲方摘要, 乙方摘要]` | 凡勃伦题不再推荐材料战/存储寡头 |
| D | **articulate 过滤**：停用词 + 最短 2 字 + 禁止残片 + 「已是卡 id 子串则抑制」；过滤后为空则 §2 整节折叠为「跳过」 | 行动单不再出现「疗政府角」 |
| E | **动态镜头顺序**：`stance_gap`/`require_involves`/`uncovered_conflicts_with` → distinguish 第一；`domain_overload`/`ghost_domain` → cluster 第一；seed-links 仅当 writes>0 置顶；articulate 仅当过滤后非空 | 盲从顺序不再导向噪声 |
| F | **seed-links=0** 时一行折叠，不占「立刻可做」主位 | 与第②轮「有 7 则置顶」兼容 |

### 6.2 中期（tension / domain 工具面）

| # | 改动 | 验收 |
|---|------|------|
| G | **`construct --tension-sample`**（或 distinguish 子模式）：输入 `--domain` / `--limit N`；输出「已有 conflict 可挂源 | 需新建 conflict | 仅语义重复可 skip」三类草案 | 第③轮不必从零写扫描脚本 |
| H | **未挂网定义升级**：`source_link_missing` ∪ `no_covering_conflict` ∪ `similarity_to_existing_conflict`；避免只看文件名 | 贸易类「思想已在、源未挂」与「真缺口」可分列 |
| I | **`consumed_buffers` 与 mark constructed 严格对齐**；未声明则不标记；可选 `--mark-buffers` | apply 日志数 = YAML 列表长 |

## 7. 设计原则（从这三轮抽出）

1. **候选必须可当输入，不可只当「同域浏览」**  
　　补 involves 的候选若不能通过「是否正文对立方」测试，就应改为「建议新建」，而不是塞一串热门卡。

2. **形式闸门要覆盖已发现的语义子集**  
　　禁止 involves→phenomenon/conflict、要求两侧、忽略 superseded——都是可机检的；继续只查「有边」会稳定地生产假安全感。

3. **诊断应同时输出「本轮禁止做什么」**  
　　articulate 过滤后为空、seed-links=0、无 overload 时，应写「跳过」；假待办与错候选一样消耗信任。

4. **digest 欠的两造，construct 可以补，但应记账**  
　　允许 stance claim 预算，并在 Journal/operation 标明「补消化结构债」，否则 skill 文案与真实工作永久打架。

5. **tension 升格是一等公民，不是 prompt 附录**  
　　第③轮证明：抽样挂网能快速提高可导航性；应用专用模式，而不是靠超长未升格列表碰运气。

6. **涌现（domain）与区分（conflict）是不同算子**  
　　第①轮与第②轮主债不同；用同一张「固定顺序行动单」覆盖，必然有一轮被误导。

## 8. 建议的下一迭代最小切片

　　若只改一件工程：**A+B+C（involves 健康度 + 忽略 superseded + 用「匹配/新建两造」替换同域候选）**。  
　　它直接对准第②轮主债，也降低第③轮「先建 conflict 再找双方」时的误挂风险；改动面限于 construct 诊断启发式与行动单文案，不碰写入事务核心。

　　第二刀：**G+I（tension 抽样模式 + constructed 标记与 consumed_buffers 对齐）**，对准第③轮。  
　　第三刀：**J（domain_rehome）**，对准第①轮可重复性。
