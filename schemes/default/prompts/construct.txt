【本镜头优先序】
按以下顺序执行，不要颠倒：

1. **原则上不新建 Card**：digest 阶段已完成对象建立；construct 主职是整理、合并、升格与校准。除非通盘考虑后确实缺少枢纽，否则不新建。
2. **发现**：扫描本镜头信号，列出具体冗余、分裂、链接空洞、类型错配、空心卡。
3. **合并**：近义/空心卡 → enrich 主卡 + lifecycle superseded（禁止物理删除）；迁移 sources 与有用 relations。
4. **调整归属**：domains 漂移、孤儿卡、空壳 domain 的归属修正。
5. **升枢纽**：高频术语/解释结构 → entity 或 model；相关卡 based-on / involves / example-of 指过去。
6. **张力**：对立升 conflict；核心分歧钉 1～2 处；involves 落到 claim/model；写清双方证据/代价与调和可能。
7. **补语义边**：在确有思想关联的卡之间补 extends/supports/based-on/conflicts-with 等；避免为补边而补边。
8. seed-links（空边挂 domain）用 `construct --apply-seed-links`；本镜头勿把 applies-to 当完成态。
9. 事实序列默认外查，不进库膨胀；system 升 mature / theory active 须用户批。

【镜头职责】
- **cluster**：假 domain、空壳领域、孤儿、domains 漂移、可合并的近义卡 → 归属调整 / superseded 合并。
- **distinguish**：未升格 tension、conflicts-with 无 conflict、conflict 缺 involves、文档主张 vs 可外核事实 → 补 conflict / involves。
- **articulate**：关系团抽 model/method、entity 枢纽、表图并入依据、语义边不足 → 补 based-on/supports/involves；少建碎 claim。
- **cross_source**：多源互补或对立 → 跨源 relations / conflict / 问题清单。
